## 一覧保存の競合

旧実装は実際の repository を使用した合成 fixture で、別々に読んだ古い一覧が後から保存され、新しい一覧を失うことを再現した。現在は読み込んだ bytes の SHA-256 を `ProjectStore.Revision` として保持し、一覧保存時にその版と現在の bytes を照合する。未ロードの store は保存を拒否し、成功時にのみ snapshot の版を更新する。ViewModel は未保存内容の基準版を保持し、診断用の別読み込みや失敗した retry で基準を進めない。既存の一時ファイルと atomic replace は維持する。

同じ正規表記の保存先を使う協調プロセスは、常設の `<projects.json>.lock` を `FileShare.None` で開き、照合から公開まで保持する。lock 中は保存が拒否され、UI は一時的な競合として再試行を案内する。版衝突では未保存状態を保持し、外部変更として区別して通知する。明示的な再読込と再適用の UI はまだない。lock ファイルは解放時に削除しない。

別 repository の stale 版、確認直前の外部変更、古い版の再試行を製品 API で検証。2つの実プロセスを barrier で同じ版から同時保存させ、一方成功・他方は lock busy または stale で拒否、既存登録が残ることを確認。強制終了後のロック解放は未検証。lock の別名・reparse alias、古いアプリや他の非協調 writer、hash 照合後から置換までの競合、電源断に対する完全保証はない。
