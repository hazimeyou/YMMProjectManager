# R20 匿名 HTTPS Pull 受け入れ

統合基準は `68259a589fd826f9d43eadaee13450a411706b37`。Windows の固定ローカル NTFS で、隔離した checkout と bare リポジトリを作成した。製品の `InspectPullRemoteAsync`、`InspectPullTargetAsync`、`PullTrustedAsync` を通して Windows のネイティブ Git と Schannel を動かした。

## 接続範囲

Python の試験サーバーは `127.0.0.1` の OS 割当ポートだけを開く。合成リポジトリへの `git-upload-pack` だけを受け付け、実際の Git smart HTTPS 応答を返す。ライブラリや応答の模倣で Pull を置き換える構成は含まない。

製品既定値では、Git の通常の証明書信頼を使い、合成証明書を拒否する。成功例では、内部の試験用プロパティに PEM を明示している。この指定は文字どおりのループバック IP に限定され、Git 子プロセスの `http.sslCAInfo` にだけ反映される。TLS の名前、信頼、期限の検証と、既定の Schannel 失効ポリシーを維持する。証明書は各試験で新規発行した短命の自己署名証明書で、チェーンの終端となる試験用信頼アンカーでもある。Windows 証明書ストア、Git の永続設定、実認証情報への変更は行っていない。

当初は一時 CA が署名した葉を使ったところ、Schannel は失効情報を確認できず拒否した。設定でこの拒否を抑制せず、専用の自己署名ピンだけを試験信頼に追加した。`SSL_CERT_FILE` と `CURL_CA_BUNDLE` の親環境変数は、実測した Schannel では試験用ルートを信頼させなかった。

## 再実行

Windows、.NET 10 SDK、Git for Windows、Python 3、隔離した YMM4 参照 DLL を使用する。リポジトリのルートから実行する。短いローカル一時ディレクトリを `TEMP` と `TMP` に指定し、必要なら使用する Python の絶対パスを `YMMPM_R20_PYTHON` に指定する。

```powershell
$env:YMM4_PATH = '<隔離した YMM4 参照 DLL フォルダー>'
$env:YMM_TEST_FILTER = 'GitHttpsAcceptanceTests'
dotnet build .\YMMProjectManager.sln -c Release "-p:YMM4_PATH=$env:YMM4_PATH" --nologo
dotnet run -c Release --no-build --project .\YMMProjectManager.Tests
```

Debug は両コマンドの `Release` を `Debug` に変更する。専用フィルターは一般回帰から独立しており、一般回帰に Python の依存関係を追加しない。ログには試験の終了コード、分類、合成 checkout の HEAD・index・ファイルの SHA-256 と、停止したサーバーの PID・ポートが出る。

## 検証ケース

| ケース | 観測と判定条件 |
|---|---|
| 製品既定の信頼で未信頼のピア | HTTP 要求が到達する前に拒否。 |
| 信頼アンカーの IP 不一致 | 信頼アンカーとして渡した証明書でも SAN と URL の IP が異なるため拒否。 |
| 合成サーバー停止 | TLS 接続を確立できず、更新候補を返さない。 |
| 承認後に先端を変更または削除 | 以前に承認した OID の適用を拒否。 |
| HTTP 503、通信切断、タイムアウト | ピア側で各要求への到達を記録し、失敗を返す。タイムアウトは `GitFailure.Timeout` を要求。 |
| 作業ツリー更新前、承認済み OID の fetch 後に先端を変更 | 実際に fetch 後の検査点に到達し、変更を再検出して適用を拒否。 |
| 匿名 HTTPS の正常 fast-forward | 実際の smart HTTPS POST を確認し、HEAD が承認済み OID と一致。index の追跡内容が承認済みコミットの tree に対応し、作業ファイルが期待値と一致。無視対象ファイルと clean 状態も保持。 |

失敗ケースでは共通して、HEAD、index の生バイトとエントリ、作業ファイルと無視対象の SHA-256、Git の状態、回復記録の有無が事前状態と一致することを確認する。fetch 後の拒否では取得済みのオブジェクトが Git のオブジェクト領域に残り得る。実ネットワーク、公開 CA、GitHub、認証必須 HTTPS、企業プロキシ、実 YMM4 は対象外で、別途受け入れが必要。
