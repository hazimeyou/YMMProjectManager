# v0.5.0 R24 引き継ぎ

判定は **R24 COMPLETE ／ v0.5.0 NOT_READY**。実GitHub公開・非公開リポジトリと実YMM4に対する受入が残る。基準はR23の `cd58d22627192aa40968f7759944c8f2aa8f4221`。統合は `codex/ymmpm-v050-r24-browser-auth-release-hardening`。試験済み実行コードは `c34255a41e8e9fab9473ad6c83d01d1f4a3bd700`。

## 完了した操作

- 接続確認は、選択中のPFに対応する検証済みGitリポジトリを対象にする。確認画面では検証したリテラルoriginと、保存済みWindows資格情報を使うかどうかを表示する。
- バックエンドは同じリポジトリの物理識別子を照合し、保持した構成ファイルのoriginが承認した1件のURLと一致することを確認してから接続する。
- 匿名接続の401、保存済み資格情報での401、403、取消、リダイレクトを分けて案内する。公開リポジトリを読めた結果だけでログイン済みとは表示しない。
- Clone、Fetch、fast-forward Pull、非force Push、確認付きCommit、個別Stage・解除は独立した既存操作を維持する。アクセス確認の完了からこれらを自動実行しない。

## ブラウザと実環境受入の再開地点

GCM 3.0.2 Windows x64の署名済み公式バイナリに一致する管理者管理インストールで、「GitHubにブラウザでログイン」「GitHubにブラウザで再ログイン」を選べる。実測したGCM 2.9.1は保存済み資格情報用のまま。ブラウザを開く前と起動時に前提を照合する。既定ブラウザで認証し、認証終了後も保存済み資格情報の選択と個々のGit操作の承認は利用者が行う。失敗と取消、期限超過、ストア更新の可能性がある不明結果を区別する。

再開時は、候補ファイルのSHA-256を照合し、承認済みのYMM4検証環境と公開・非公開の専用リポジトリを使う。公式GCMを管理下で導入し、初回ログイン・再ログイン・ブラウザ取消・資格情報失効・複数アカウント・選択したリポジトリのGit操作を確認する。その後、実YMM4で導入・更新・復旧とYMMPX受け渡しを受け入れる。

YMMPXの対象範囲と旧版の証拠は試験結果を参照。ローカルの検証候補を組み立てた。正式公開の条件にはブラウザ認証を含む実環境受入が残る。NAS受入は今回の必須条件外。
