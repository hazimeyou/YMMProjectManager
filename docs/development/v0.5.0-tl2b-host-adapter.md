**IMPLEMENTED / DISABLED**。ホスト非依存の調停、描画順序、画素の所有、結果の検証を実装した。YMM4 SDK に接続するアダプター、製品への登録、既存プレビュー・編集コマンドへの接続は含まない。

## SDK と PM の調査結果

TL-1R/TL-2A の契約と YMMPrint R2 の `5140548669b5d136802d967875ca18c2da6333ce` を確認した。YMMPrint の `docs/research/tl-preview-r2-pm-handoff.md`、`tl-preview-r2-acceptance.md`、`research/TlPreview/Probe/NativeSceneTarget.cs` が根拠。5 SDK 版の Release/Debug コンパイルと A→B→A の合成実行を確認した。公開経路は `Scene.TryCreateVideoSource` → `Update` → `RenderBitmapSource`。静的 IL には GPU デバイス・コンテキストの生成と解放、ViewModel から共有設定への参照がある。実リソース独立性、プレビュー・書き出しとの競合、SDK 内部の同期や再入は **UNVERIFIED**。

取得候補は承認されたツール文脈の `TimelineToolInfo.Timeline / Scenes` と `Scenes.AllScenes`。YMMPrint の ToolProbe は Timeline GUID で探索する研究実装。PM の `TimelineContextService` は既存ツール文脈の保持に留まり、所有・寿命の信頼できる判定器には使えない。将来の取得処理は正規の owner の下で Timeline 参照同一性、Scene membership と親文脈、候補の一意性を照合する。Scene wrapper の再列挙時の安定性、プロジェクトの owner とリビジョン、終了・置換の失効契約は実機で確認する。権威ある検証ができない場合は処理を開始しない。

## 描画順序と寿命

1. `SceneComparisonPlan` でセッション、同一プロジェクト・リビジョン、別 Scene、寿命、フレームと設定を結び付ける。調停器は呼出しのたびに A/B と A 再取得へ別の操作 ID を発行する。元の正確な要求 tick と解決フレームを保持し、A 再取得の評価条件を A 初回と一致させる。
2. 正規の UI Dispatcher 文脈で、新しい A/B 観測と編集状態トークンを取得する。取得直前と描画直前に、ホスト実装が owner・リビジョン・object lifetime を再検査する。借用 Scene、Timeline、UndoRedoManager、AsyncAwaitStatus はホスト所有のまま。アダプターが閉じるのは自身が取得した描画源だけで、source の Devices を別途解放しない。Open が描画源を返す前の失敗は、Open 実装側が部分取得の後始末を保証する。
3. A→B→A を逐次処理し、Open 後と Render 後にも新しい状態を確認し、失効時は次の処理へ進まない。各 source の有効期間内に応答の操作、Scene、相関フレーム、寸法、形式、stride、長さを既存 TL-2A 契約で検証して独立コピーする。source は各区間の成功・失敗・取消時に1回閉じる。独立コピーは最大3枚（各32 MiB）。ホストの借用・GPU リソースはこの上限に含まれない。応答の `FrameIndex` は実描画を確認した値が必要。SDK の `BitmapSource` はフレームの証明を含まず、要求値の復唱ではこの条件を満たさない。
4. A の2回の画素を完全照合してから A/B のメトリクスを計算する。設定や初期状態、編集状態に差があるか取得できない場合は結果を返さない。最終観測も必須。A/B の一致はフレーム画素の結果であり、素材の同一性・参照先・再リンクの正しさは別途確認する。

## 排他・取消・故障

`SceneRenderCoordinator` は参加経路が共有する1セッション1インスタンスを想定する。所有区間は最初の観測から最終観測まで。原子的に取得し、進行中の重複または再入は `Busy` で直ちに拒否する。Dispatcher への同期転送、待機キュー、ロックを保持したブロッキング待機は実装していない。別インスタンスや SDK 外部のプレビュー・書き出し・他プラグインには効かない。ホスト全体を対象とする排他は将来の接続元が実証する。描画と解放のスレッド契約も接続元で検証する。

単調時計の期限と呼出し元の取消を SDK 呼出しの前後、比較前後などの境界で検査する。期限で `TimeoutException`、取消で同じトークンの `OperationCanceledException`。両方を同じ境界で検出した場合は取消を優先する。同期 SDK 呼出し中の強制中断は扱わない。返ってこない呼出しは source 解放やゲート解除もできないので、隔離環境の停止・復元手順で扱う。

source 解放に失敗した調停器は隔離状態に入り、後続要求を `CleanupFailed` で拒否する。漏れの有無とホスト状態を確認してから、接続側が新しい安全な実行範囲を確立する。元の処理と解放または最終観測の両方が失敗した場合、両例外を AggregateException に保持する。通常の診断は分類と側のみで、SDK 例外の詳細を表示・保存する場合は生のパスや素材情報を除く。

## ピクセル契約

R2 は WPF `BitmapSource` の元形式と寸法を確認し、必要に応じて WPF で変換してから幅×4の**コピー先 stride**でコピーする。元 stride、実出力の straight/premultiplied、色空間・伝達特性、DPI は実機未確認。DPI は画素の byte 変換に使用せず、描画やスケーリングに作用する場合は設定として検証する。

通常の受け渡しは TL-2A と同じ straight BGRA32。明示的な実験用 `CopyExperimentalPbgra32` は同じサイズ・stride・所有・取消の境界内で、宣言済み Pbgra32 のみを変換する。各チャンネルの整数式は `(Cp × 255 + floor(A/2)) / A` を切り捨て（最近傍、同値は上方向）。alpha は保持する。A=0 は RGB=0 のみ有効、A=255 は恒等、Cp>A は拒否。元の RGB を復元できない場合があり、色管理も行わない。たとえば Cp=64、A=128 ではこの式は128、R2 の WPF 合成出力は127。実験変換は調停器から呼ばれず、実ホストの形式・色・丸め契約が確定するまで自動採用しない。
