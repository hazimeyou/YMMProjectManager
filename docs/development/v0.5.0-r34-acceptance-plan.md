# R34実環境受入計画

R33では実YMM4とVMを操作していない。ここでは受入先、検査用PF、停止条件と合格証拠を定める。

## 受入開始条件

- 承認済みのWindows 11 x64環境でYMM4 Lite 4.57.0.1と.NET 10の版を記録する。YMM4、設定、プラグイン、PF、素材、テンポラリ、ログを試験専用領域に置く。本番のバイナリ・ワークツリーへの配備先が解決された場合は停止する。
- 正式なYMM4で一度保存した試験専用PFを基準にする。合成試験の最小JSONは実YMM4読込を証明しない。すべて新規名の複製を使い、元PF・素材・一覧・設定のSHA-256を開始前に記録する。
- 本番ネットワークは不要。GitHub受入だけ、別途承認した専用リポジトリと権限の用途を決めて実施する。素材と秘密情報を試験リポジトリやログに含めない。

## 試験データ

| ID | 作成するPFまたは状態 | 比較・確認の狙い |
| --- | --- | --- |
| PF-A | 24 fps、約130秒。色板または文字で先頭、59秒台、60秒、119秒台、120秒、最終フレームを区別する | 64点取得の両端、区間開始、終端 |
| PF-B | Aを別名保存し同じ論理Scene IDが残ることを検査。30 fps、約140秒。目印をAと異なる位置に置く | 別の物理PFと版、異なるfps、同じScene IDの別寿命 |
| PF-C | 二つ以上のScene。比較対象外のSceneにも別の目印と未保存変更を用意する | 対象Sceneと別Scene、独立寿命、操作対象外の編集保全 |
| PF-D | 画像・動画・音声を一つずつ参照。試験用素材の一つを別名のまま退避し、元名とSHA-256が一致する候補、名前だけが一致する候補を別の試験フォルダーへ用意する | 欠落検出、厳格照合、別名PF保存、Undo/Redo |
| PF-E | 1フレームの短尺と長尺Aを用意し、生成待ち中に選択変更や取消をする | 64スロット、重複フレーム、取消後の結果とキャッシュ |

比較の入力は共通時刻0秒、59.999秒、60秒、119.999秒、120秒、左と右の終端付近を含める。固定オフセットを−2秒、60秒開始を+10秒、120秒開始を−5秒に設定する。区間開始を含み次の開始は含めない。開始がない区間では固定値を使い、範囲外の側は空の表示と理由を示す。比較の設定を別名で保存し、別セッションで読み直す。

## 実ホスト検査

1. **独立Sceneの所有を先に測る。** PF読み込み時に物理ファイルIDと完全SHA-256を保持する。描画側で実セッション、ロード済み版、Sceneのインスタンスと寿命を独立観測する。要求値の反復を観測値にしない。同じScene IDの別版と、同じScene実体を誤指定した組を両方検査する。正規の終了・取消・初期化失敗でVideoSourceと関連資源の解放を計数する。
2. **読取専用描画を検査する。** プレビュー・エクスポート・選択変更と競合させる。対象PF・フレームが変わった結果と取消後の結果を公開しない。開始・終了のシーク位置、Scene選択、dirty、Undo/Redo、元PFのハッシュを比較する。フレームの目印と実際の画素形式・strideを記録する。
3. **Timeline再リンクの書込み契約を独立に検証する。** 事前スナップショットにはセッション、PF版、対象Scene、各アイテム参照、変更前パス、確認済み素材ハッシュ、編集・Undo状態を含める。複数setterの途中失敗、アイテム差し替え、Scene切替、利用者の別編集、Undo/Redo各1回を試す。編集中にデータを別の版へ上書きする復旧策は採用しない。ホストが原子的な編集と履歴記録または確認可能な巻き戻しを提供できなければ反映を停止し、別名PF経路を使う。
4. **GitHubの受入を独立実施する。** 既定ブラウザ認証、再認証・取消、認証失効、権限不足、origin変更、公開・非公開Clone、Fetch、確認付きPull、非force Pushの状態を専用リポジトリで照合する。Pushの拒否試験では実アップロード前の停止を確認する。

記録項目は試験ID、対象HEAD、参照DLLと導入物の版・SHA-256、fixtureハッシュ、操作記録、実画面、受入PASS／FAIL／NOT_RUN、保全証拠と再現手順。認証トークンや実ユーザーのパスを証跡に残さない。実ホストに依存する判定は隔離参照DLLと合成UI試験の結果から確定しない。
