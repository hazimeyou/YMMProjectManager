# v0.5.0 TL-2B 実機受入計画

**BLOCKED / REAL-HOST ACCEPTANCE: NOT_VERIFIED**。以下は未来の明示承認された実行の手順。2026-11-21 の TL-2B 準備では YMM4 を起動していない。

## 起動前チェック

- [ ] 管理者が対象 Windows/VM、対象ホスト、YMM4 の版とビルド、操作と証跡保管を明示承認した。共有 VM と YMMTestLabManager の利用は別途明示承認を確認した。
- [ ] 合成専用のプロジェクト・素材・プラグイン・設定領域に隔離した。ホスト/ゲストの共有、同期、共有フォルダー、資格情報、実データへの到達性を確認した。
- [ ] バックアップまたはスナップショットと復元・停止手順を確認した。YMM4、設定、プラグイン、合成プロジェクト・素材の起動前ハッシュを記録した。
- [ ] 同じ合成プロジェクト内に青系 A と赤系 B を用意し、各フレームに Scene ID とフレーム番号を読める形で埋め込んだ。A を可視、B を非アクティブとする。末尾と範囲外を確認できる尺を用意した。
- [ ] owner、Scene の参照、プロジェクト寿命・リビジョン、Dispatcher、SDK 上の実フレーム対応、ホスト全体の描画排他を実測する手段を用意した。状態の観測手順は [観測表](v0.5.0-tl2b-state-observation.md) を使用する。
- [ ] 証跡に含める合成画素とログ、計測器、反復回数、タイムアウト、メモリ・GPU・UI の受入基準を実行前に承認した。

## 手順と判定

1. 隔離設定を確認して対象 YMM4 を起動し、合成プロジェクトを開く。プロジェクト owner、所属 Scene 候補、Scene と Timeline の参照同一性、リビジョンと寿命を記録する。所属や一意性を確認できない場合は中止。
2. アクティブなプロジェクト・Scene と可視シークを記録する。A/B の CurrentFrame、選択・レイヤー、Undo/Redo の履歴・カーソル・変化通知、dirty、コマンド、プレビューの前状態を取る。観測不能項目はその場で明記し、成功に計上しない。
3. 同一設定で、A1・B・A2 を個別の操作 ID で順に取得する。各呼出しで要求 tick、対応する Scene FPS・frame、SDK へ渡した時刻、画素から独立に読んだ Scene ID・frame、寸法・元形式・alpha・色空間・DPI・判明した stride を記録する。各 source の取得・解放を記録する。元 stride が API 上取得できなければコピー先 stride と区別する。
4. A1/A2 の完全一致と B の期待 Scene/frame を検証する。B は期待する基準画素とも照合する。先頭・中間・末尾、範囲外、順序を逆にした反復、非アクティブ B を検証する。異なる FPS が同一プロジェクトで実際に成立する場合は、対応時刻、たとえば 500 ms の24/30 fpsで A12/B15 を検証する。
5. 各区間後と終了時に状態を再観測し、可視シーク、アクティブ Scene、選択、Undo/Redo、dirty、コマンド、既存プレビューを突き合わせる。通知を調べて一過性の変更も対象にする。実機側のプレビュー・書き出し・別比較の競合を許可された範囲で試し、排他と再入拒否を確認する。
6. 取消を描画前、描画直後、コピーと解放の境界で試す。期限後の結果が公開されないこと、source の解放、状態再観測を確認する。失敗経路も同様に試す。SDK が応答しない場合は隔離手順で停止し、状態と証跡を保全する。
7. 条件ごとに UI Dispatcher の応答時間、処理時間、private/managed メモリと GPU メモリ、source の生成・解放数を測る。反復後や閉じた後も測り、事前承認した基準と照合する。
8. プロジェクトを閉じ、Scene 置換や再読込で古い操作と参照が失効することを確認する。通常終了後にハッシュ、設定とファイルの差分、出力先、復元を確認する。権限・排他・寿命・画素形式・状態保全のどれかが未確立、または異常なら当該項目と製品接続を保留する。

二つの native panel、入れ子 Scene、別プロジェクトを同時に扱う受入は、この手順の同一プロジェクト二 Scene とは別に記録する。最終判定は手順単位で PASS / FAIL / NOT_RUN / UNOBSERVABLE と証跡を残す。
