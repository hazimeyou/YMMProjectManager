# v0.5.0 R18 統合進捗

基準は R17 の `6d11d6c0426e9f5cf0b7ae8661bb42eeb2d79b09`。R17 最終実行コード `99176ed` からの差分は文書7件。過去ログの Release / Debug、実 YmmpxLib あり / なしの全4構成で各62グループと計測済み個別71件の成功を確認した。R18 は独立した worktree と3つの worker worktree で実施した。

## コードと検証

- Git 読み取り診断は graft を含む履歴を判定外とし、追跡 ref が診断中に変更・削除されたら再確認を求める。ブランチ切り替えに `--no-overwrite-ignore` を指定し、衝突時の作業ファイル、HEAD、index の保存を確認した。書き込み Pull はサービスと UI の両方で拒否する。 [判断と中断実験](../architecture/adr/git-pull-recovery-r18.md)
- 一覧の復旧では公開候補の物理 ID と SHA-256 を照合する。旧レシート v1〜v3 の読込を維持。下書きと新レシートは作成時のハンドルを保持したまま確定名で公開する。開始済みレシートを公開する直前に準備記録を封印し、以後に中断すると回復判定は Unknown。子プロセス中断後も下書き・証拠・現用一覧を保持する。 [一覧保存契約](../architecture/adr/project-list-publication-r17.md)
- 管理付き再リンクは検証した履歴をハンドルで保持してから新規出力を公開する。実ファイルと親の照合が完了するまで操作の先へ進まない。明示の未公開出力再開と、競合時の非上書きを回帰確認した。
- 現行 YMMPX の新規作成は、選択した元プロジェクトの JSON とパッケージ内の JSON を照合する。書き換えた素材参照ごとに元ファイルと同梱データのサイズ・SHA-256 を照合する。同名素材、Unicode、無関連プロパティの保持を実 DLL で確認した。
- 外部素材の読み取りは、ディレクトリと実ファイルのハンドルを用いる。親が欠落した素材は Missing、読み取れないファイルは Unreadable と分類する。素材一覧の出力は同名保存の勝者1件だけを公開し、失敗側は自身の一時ファイルだけを処理する。Windows ファイル共有の試験結果に基づいて、一覧・素材・再リンクの親ディレクトリ持ち替え防止を対象箇所に追加した。
- WPF は Pull が無効な理由、診断対象ルート、ローカル追跡 ref を表示する。一覧を開く際に別ライターのロックで失敗した場合は、画面上で再試行できる。中断確認の取消は回復欄に表示する。
