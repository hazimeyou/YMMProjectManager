# v0.5.0 R24 試験結果

試験は隔離Windows x64環境で実施した。SDKは10.0.404、Windows Desktop Runtimeは10.0.15、YMM4の参照本体DLLはファイル版4.57.0.1。YMM4参照DLLは既存の隔離コピーを使い、`YMM4_PATH` と `YMM4DirPath` の両方をビルドごとの試験領域へ設定した。実行ごとに固有の `TEMP` と `TMP` を設定。実ライブラリありの回帰のみ、隔離して複製した実YmmpxLib 1.1.0を `YMMPX_LIB_PATH` で指定した。実YmmpxLibのSHA-256は `107A522AAC5C0AAFD32494C0C93AC9404694FBA6A4BAD7902B78D0F000C2E552`。旧版は公開タグ v0.2.1、v0.3.0、v1.0.1 のCLIで生成したR23の合成fixtureを再利用した。本番YMM4、実GitHubアカウント、共有VMは使っていない。

```powershell
dotnet build .\YMMProjectManager.sln -c Release '-p:Version=0.5.0' "-p:PathMap=$((Get-Location).Path)=/_/src" --nologo
dotnet build .\YMMProjectManager.sln -c Debug '-p:Version=0.5.0' "-p:PathMap=$((Get-Location).Path)=/_/src" --nologo
dotnet run --project .\YMMProjectManager.Tests -c Release --no-build
dotnet run --project .\YMMProjectManager.Tests -c Debug --no-build
```

全回帰では `YMM_TEST_FILTER` を解除。隔離HTTPSは `YMM_TEST_FILTER=GitHttpsAcceptanceTests` の別枠。旧版合成fixtureの場所は `YMM_TEST_YMMPX_RELEASED_FIXTURES` に設定。個別件数はランナーが明示計測したケースに限る。古い子プロセスの内部チェック等は個別数に含めない。

## 認証境界の追加証拠

- 同一形式の2リスナーをループバックに配置し、GCMのGitコマンドスコープに明示プロキシを設定した。標準出力・標準エラーを廃棄し、資格情報ストアを無効にして合成値のみでテスト。2.9.1実行ファイルはプロキシ0・宛先への直接TCP 1で非0終了、署名とSHA-256を照合した3.0.2実行ファイルはプロキシへの正確なCONNECT 1・宛先への直接TCP 0で非0終了。後者ではプロキシが意図的に拒否した。
- 公式v3.0.2のソースからビルドしたGitHubOAuth2ClientとHttpClientFactoryを同じTLS境界の合成試験に接続。通常のコード交換、307・308の許可外転送を別々に試験し、通常交換の成功と拒否対象のTLSサーバーへの到達0を確認。実ブラウザの起動・コールバックからWindowsストアへの本物の保存を検証した結果ではない。
