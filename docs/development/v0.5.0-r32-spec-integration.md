## 判断の根拠

除外・素材選定は [YMMResourcePackager 2a767c8](https://github.com/hazimeyou/YMMResourcePackager/tree/2a767c8b4922cb0aa1f0cf6fdaf8a3ea6a0bc53a) および公式YmmpxLib 1.1.0を基準にした。PMの同梱画面と非上書きの出力契約を維持している。

- PackagerとPMの保持先を分け、同じ形式を確認して取込する。Packagerが除外JSON解析失敗を空と扱うケースでも、PMは停止する。承認ルート外の参照は読まない。連番の各候補を検査し、対象外の実体を一時コピーしない。標準の格納名が旧PM専用予約名と衝突し得る場合は、標準パッケージの参照を維持したまま別名を使う。存在している除外設定は公開時に物理IDと内容を照合して保持する。未作成設定は公開直前の不在を再検査するため、協調しない別プロセスがその検査直後に作成する境界は残る。
- 既知の公開拒否は対象ツリーと送信到達履歴に適用する。未知の変換、任意の秘密形式、PM外の操作を完全に防ぐ保証はない。旧ログは個人情報を含み得るため製品ログの名称も拒否対象に含める。
- 診断ログへ保存する情報は操作名・レベル・例外型・HResultに絞る。回転後のログは所有記録・実体ID・長さ・SHA-256を照合して削除する。完了キャッシュは所有記録を持ち、各フレームの物理IDと内容を照合する。旧キャッシュ、未完了キャッシュ、上限を大きく超える旧ログなどの未知ファイルは保全する。容量表示は確認できた領域を対象にする。ドライブ全体や別プロセスの書込みを一括制限するものではない。
- [D09調査記録](v0.5.0-r32-host-evidence.md) のホスト受入が次の境界となる。既存Timelineをシークする経路は停止したまま。YMMPrintが使う現在Sceneからの描画APIを確認したが、保存済みPFと比較元を別個のSceneでロードし、実体と寿命を独立に観測する契約は残る。

- YMMPX担当は隔離worktreeで除外・標準作成・旧形式互換を実装した。作業元は `1023ad93d95fc9dd20bb6fce31dfbc419ee81b61`。差分を `a70abcaf5df693cc882120f8b07682243ae890f4` として取り込んだ。v2の試験は固定JSONから実行時に合成し、中間コミットのアーカイブを統合履歴に含めていない。
- 旧機能撤去担当は `bb53a0c2542b6b04c916f697580c2683920123ca`、統合 `8583701`。ホスト調査担当は `298ffdaa808e360b1290c53e12ea53bb12395de2`、統合 `57cde52`。独立したworktreeと担当範囲を保った。

## 基本の検証手順

YMM4 Lite 4.57.0.1の参照DLLを隔離領域に置き、`YMM4_PATH` と `YMM4DirPath` に指定する。TEMPとTMPも短い名前の専用試験フォルダーに設定する。長い試験親パスでは、旧Git素材プールfixtureがGitのパス長制限を超えることがある。`dotnet build YMMProjectManager.sln -c Release` と `-c Debug` を実行し、それぞれの試験用アプリホスト `YMMProjectManager.Tests.exe` を実行する。実ライブラリありでは公式の `YMMPX_LIB_PATH` を指定し、なしでは環境変数を解除する。公開版由来の合成旧形式サンプルがある場合は `YMM_TEST_YMMPX_RELEASED_FIXTURES` に指定する。隔離HTTPSは `YMM_TEST_FILTER=GitHttpsAcceptanceTests,RealYmmpxR5Tests,R30InstalledYmmpxLibTests` で明示選択する。
