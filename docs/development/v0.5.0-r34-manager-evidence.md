## 証拠回収、停止、再試験

1. 実機枠の承認時にVM、候補DLLと依存資産、試験定義の版、合成PF、許可操作、回数、期限を固定する。R15の実装は全体120秒のうち8秒を終了・証拠処理用に確保する。別の予算は管理側が再審査する。
2. 実機直前にWindows版、標準ユーザー・Medium Integrity・対話型Basic Session、NIC切断、リダイレクト・共有の不在、保護チェックポイント、関連プロセス、Queue・lease・未解決Recovery、観測の鮮度、候補とPFの再ハッシュを確認する。不一致や証拠不足で開始を止める。
3. 新規Run IDを開始記録、ジャーナル、Worker、受領書、HOST転送に連結する。対象画面の一意性はプロセス、ウィンドウの所有関係と識別情報で確かめる。対象同定の失敗や曖昧さは診断扱いとし、別の対象への操作を停止する。
4. 目的の画面を取得した `window.png`、診断用の `diagnostic.png`、確認するログ・出力を役割別に保持する。HOST回収は各ファイルのSHA-256、対象との対応、終了コード、結果の確定、lease解放、VM隔離とQueue前後比較まで照合する。診断PNGのみ、結果不明、未解決Recovery、欠損・改変はPASSを阻む。
5. タイムアウト、終了不明、lease残存、保全条件の不一致では試行を停止し、原本を保存する。管理側の別手順で開始有無、関連プロセス停止、lease解放、証拠確定を調べ、Recovery解決記録を追加する。許可が残り、原因と修正、新しい資産ピン、隔離観測、Recovery解決を確認した場合に限り、新規Run IDで再試験する。
