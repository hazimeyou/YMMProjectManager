## A ライブサムネイル

公式YMM4 Lite 4.57.0.1の参照DLLを静的に確認した。`MainViewModel.OpenProject` が `MainModel.LoadProjectFile` の処理を呼び、`Json.Load<Project>` が `FileMode.Open`、`FileAccess.Read`、`FileShare.Read` でJSONを読む。ストリームはモデルが返る前に閉じる。その後、旧形式・素材パス・移行処理を経て `MainModel.OpenProjectAsync` がScenesとTimelineを確定する。`TimelineToolInfo` と保存済みフラグには、元ファイルの物理ID・読み込んだ版を渡す契約がない。

| 方式 | 判定 |
| --- | --- |
| 既存モデルと現在のパス・保存済みフラグを照合 | 読み込んだ後に同じパスで差し替えられたPFを区別できない。 |
| 現在のモデルをシリアライズしてPFと比較 | 読込後の移行・パス変換があり、元バイト列との対応を証明できない。 |
| ファイルを先に保持し、読込完了時にモデルと結ぶ | 合成NTFSでReader同士の共存と書換え・改名の拒否を確認した。現行のShellExecuteに操作単位の完了応答がなく、私有のOpenProjectは確認・バックアップ・編集状態の変更を伴う。 |
| オフスクリーン描画 | WindowsFormsHostのハンドル、GPU、ホスト設定との関係を分離して検証する必要がある。 |

取得開始後に選択やPFパスが別の値を経由して元に戻ると、旧来のその時点だけの比較で検出できなかった。状態が一度でも変化した操作を無効化し、元フレームと先行キャッシュの保全を合成fixtureで確認した。統合コミットは `a70b491`。証拠のないホストからの新規取得は既存の安全停止を維持し、取得UIと新旧キャッシュ読込を維持する。隔離ホストの明示承認後、ファイルを開いている間の物理ID・SHA-256と、対応するロード完了、モデル、Scenes、Timeline、プレビュー所有者を一つの操作として照合する経路から再開する。


## B 世代manifestの競合

R28では、読込後に別の物理ファイルが同じSHA-256で置かれると、更新で外部ファイルを置換できた。合成fixtureのサービス呼び出しで再現した。R29は、一覧を読み込んだファイルの物理IDとSHA-256を一緒に保持する。更新時はディレクトリを固定し、manifestごとのプロセス間排他を取得し、確定直前に同じファイルの同じ版であることを排他ハンドルから確認する。

置換前のハッシュ比較だけでは比較と置換の間に別プロセスが更新できるため、照合済みのハンドルで動かす方式を採用した。変更を受け付ける場合は旧版を固有名に退避し、検証した候補を空の現用名に公開する。協調しない処理が現用名を先に作った場合は、候補の公開と旧版の復帰のどちらも非上書きで行い、競合ファイル、旧版、候補を残す。旧版退避後のプロセス終了も検証し、現用名が空の状態を初期化で埋めない。世代の作成・削除の失敗時は、実際に所有しているデータだけを片付け、回復に必要な候補や退避世代は保持する。

製品の作成・削除は読み込んだ版を更新条件にする。呼び出し互換の全体書込みAPIは呼び出し開始時点の物理版を検証するため、呼び出し前に作られた引数の古さまでは判断できない。任意の外部ツールとの共同トランザクション、別ボリューム・NAS、電源断の耐久性は保証対象外。復旧時は、同じ操作識別子を持つ `manifest.json.previous-<operation>` と `manifest.json.tmp-<operation>` 、現用ファイル、関連する世代ディレクトリを保全してから比較する。

## C 元PFと設定の中断回復

元PFの後退や再実行で別ファイルを壊さないため、元ファイル・候補の物理IDとSHA-256、現用パス、元PFの退避先、候補パスを含む操作記録を、元PFの退避前に非上書きで作成する。保存名は対象PFの親フォルダーに置く `.ymm-restore-<名前のSHA-256>.pending.json`。記録が残る場合は既存の復元操作を停止し、記録の所在を返す。操作記録のパスを命令として自動実行する仕組みは持たない。回復時は現用PF・回復記録・退避と候補を保全し、記録とSHA-256を照合して別名で作業する。置換後の元PFは従来のバックアップへ保全する。

OSのプロセス終了試験では、manifestと元PFそれぞれで旧版退避を通知してから子プロセスを終了させた。保持された版と候補を照合し、一覧の空初期化や元PFへの無条件再試行を拒否することを確認した。通常復元、取消、保存先競合、世代作成・削除も同じサービス経路で検証した。統合コミットは `1340ca0`。

R28の合成再現では旧版退避直後にプロセスを終了すると、元の名前が空き、`.previous-*` は残った。新しい設定サービスは読み込みと保存を拒否した。R29では公開前に、対象ファイル名、ディレクトリの物理ID、旧版と新しい候補の物理ID・SHA-256を固有の回復記録へ書いてFlushする。旧版と確定前の候補が両方残り、唯一の操作についてすべてが一致する場合、設定画面の「再読込」から利用者確認を経て旧版を戻せる。再確認と公開は元のハンドルを保持して行い、非上書きの移動で競合先を保全する。YMMProjectManagerSettings.jsonの形式は従来と同じ。

自動復元は、別操作の公開後に現用ファイルが外部操作で消えた場合に意図しない巻き戻しとなるため採用しなかった。候補の存在・物理ID・ハッシュを確認するまで回復を提示しない。R28由来の記録なし退避、複数候補、破損、外部変更は手動で保全・照合する。設定で再読込が失敗した場合は表示された退避先を確認し、現用ファイル・旧版・記録のコピーを別名で検証する。電源断耐性は未検証。

OSのプロセス終了を使用し、子プロセスは旧版の退避が完了した時点でイベントを通知する。試験はプロセス終了後も残り得るNTFS共有ロックが解放されたことを確認してから再読込する。旧版の物理ID・内容、競合現用ファイル、記録破損、複数候補、他ディレクトリの記録、既に公開した候補の識別を検証する。以前の退避名と既存のJSON書式はそのまま扱う。


Gitへの誤公開を防ぐため、復元記録・一時PF・退避用の固有名を、Stage、Commit、Pushで使う公開検査に追加した。履歴に残った後で削除した候補と、別名にした記録も合成リポジトリで拒否することを確認した。標準PFと予約外の名前は従来どおり扱う。一般のPFと同一形式の退避コピーを任意の名前へコピーした場合まで一律に識別する機能ではない。統合コミットは `39f2c4d`。

## D 配布workflow

タグの照合後、読取り権限のみのRelease・Debugジョブで固定版のSDK、YMM4参照、配布版YmmpxLibを使用する。両構成で実ライブラリ有無の全回帰、隔離HTTPS、実ライブラリでの作成・展開を実行する。試験済みアプリ・テスト実行ファイル・参照DLLと配布物のSHA-256を記録し、Release成果物のZIP内バイト列も照合する。`.ymme` のファイル構成は従来と同じで、エントリの順序とタイムスタンプを固定した。GitHubのドラフト作成に必要な書込み権限は、両ジョブが成功した後の処理に限定する。
