# v0.5.0 R19 統合進捗

R18 最終 `2a0176f3cceb189c6e89155cb6bc8e6d40786e7e` を基準とした。R18 の実装 `dec3378` 以後は文書だけだった。基準の Release・実 YmmpxLib ありを再実行し、警告0、エラー0、62グループ・個別計測93件成功、書き込み Pull 1件スキップを確認した。

| 担当 | 原コミット → 統合コミット |
|---|---|
| Git service・受入 | `25fed2b → 2180470`、`1b5e886 → 31d8bd5`、`5e8c2a2 → 4a8b5b6`、`b0fc3ef → a69fb51` |
| WPF | `a1cf7be → d915eea`、`9d641aa → 0286d99` |
| 回復・独立レビュー | `c94cfc6 → 4fd3bc5` |
| Controller | `d31260e`、`b9cdadb`、`2b2d8d9`、`c5c03db`、`149458e`、`88b0c87`、`b17db4f` |

- Git の隔離試験で、大小文字のみ異なる2ファイルを含む Git tree が Windows でコマンド終了コード0になり、index に2件が残る一方、作業ツリーでは片方だけになることを確認。製品は最終更新前に対象 tree を検査し、この状態を拒否する。
- 初期の同期回帰で `GIT_GRAFT_FILE=NUL` に対する Git の助言が正常な更新を拒否させる不具合を発見した。既知の助言だけを Pull の設定で抑止し、実 Git と WPF の成功経路を再試験した。
- R18 の読取り診断では設定確認と status が別プロセスで、設定が途中で変わり得た。R19 では通常の worktree 確認もローカル設定ファイルを保持して制限した Git プロファイル内で行う。変更された設定は次の観測で比較する。
- UNC の別表記と固定ローカル NTFS 以外のパスは、ローカル接続対象として問い合わせる前に除外する。UNC の確認は構文だけを用い、実ネットワークへの接続を行わなかった。
- すでに承認済みの tree に `filter` 属性がある場合、外部フィルターを抜いたまま更新する前に保全停止する。Git の表示上の未指定と文字列 `unspecified` を区別するため、`git check-attr --all` で明示された属性そのものを調べる。対象 tree と属性を読む subprocess の各出力は8,388,608 UTF-16 コード単位を上限とし、超えた場合は照合不能として扱う。
- Git の正常終了直後、製品の事後照合の前でテスト子プロセスを終了した。再起動後の別インスタンスは、現用の ref、index、作業ファイルが更新済みであっても、回復記録を保持し再承認を拒否した。
