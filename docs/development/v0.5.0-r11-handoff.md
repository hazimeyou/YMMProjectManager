## Build / test

Windows、.NET 10 SDK、WPF と YMM4 参照が必要。`YMM4_PATH` に隔離コピーの参照 DLL を入れたディレクトリを指定し、`TEMP`、`TMP`、`YMM4DirPath` も隔離領域に設定する。csproj の `CopyToYMM4` は build 時に `YMM4_PATH` 以下へ出力するため、本番 YMM4 を指定しない。

```powershell
dotnet build .\YMMProjectManager.sln -c Release "-p:YMM4_PATH=$env:YMM4_PATH" --nologo
dotnet run --project .\YMMProjectManager.Tests\YMMProjectManager.Tests.csproj -c Release --no-build
```

実 YmmpxLib 条件付き試験は DLL の隔離コピーを `YMMPX_LIB_PATH` に指定して別プロセスで実行する。DLL 不在と停止中機能は skip として報告される。runner の数値は top-level group のみ。R11 の統合結果は 56 group pass / 0 fail / skip 3、Release build warning 0 / error 0。

## 読む順序と責務

1. `Application/ProjectStore.cs` と `Infrastructure/JsonProjectRepository.cs`: snapshot revision、協調ロック、原子的な一覧保存、安全に再保存できない入力の拒否。
2. `Application/ProjectListRecovery.cs` と `Presentation/ViewModels/ProjectListViewModel.cs`: ID 設定の未保存状態と限定された競合回復。property / collection mutation、UI await 中の変更と部分成功を重点確認。
3. `Infrastructure/AssetManifestStore.cs`、`Infrastructure/Relink/`、`Presentation/Relink/`: ID 検査、create-only revision、候補 hash と SaveAs。revision head と relink 後回復は未完成。
4. `Infrastructure/GitRepository.cs`: shell を使わない Git 起動、remote の信頼境界、停止中の Pull。条件付き ref 更新だけでは checked-out worktree の整合性を保証できない。
5. `Infrastructure/Packaging/`: archive preflight と作成、停止中の extraction、installer の cancellation。外部 DLL の同期 API と絶対参照を重点確認。

## 動作・制約

利用可能な範囲には project 一覧、明示的 legacy ID / metadata ID 関連付け、素材検査、ファイル側 relink SaveAs、YMMPX の新規作成、Git local 操作がある。metadata パスの永続関連付け、move/copy、revision head、relink 後 recovery は未完成。Git remote UI / Pull、timeline mutation、YMMPX bridge extraction は安全停止中。列挙は実ホストでの受入を意味しない。

一致しない一覧 revision の再現: 合成 JSON を2 repository で読み、片方を保存し、もう片方を保存する。後者は衝突例外となり、前者の保存内容を保持する。ID だけの保留であれば画面上の「ID 設定の競合を回復」で最新一覧へ再適用できる。複数種類の未保存変更・未知項目を含む場合は停止し、元データを維持する。

既知の技術的負債: 非協調 writer の hash 照合後の競合、回復中の project hash 処理に取消 UI がないこと、installer 部分ファイルの cleanup、長パス時の Git 自体の制約、全個別テスト数と実ホスト互換性。`ProjectStore` を自前生成して保存する API 呼出元は読み込み済み revision と `IsRecoverySafe` を引き継ぐ必要がある。既定 Version は `0.4.0` のため、将来の release 作業で明示的な整合確認が必要。
