# R21 素材プールと厳格な再リンク

## 収集と保管

収集時に指定するのは素材ファイル、元の参照、既存の保存先フォルダー、素材を使用したコミットの完全な OID。URL と再配布許諾の記録は任意。許諾の記録は利用者のメモであり、権利の判定には使わない。元参照には作成者のパス情報が含まれ得る。

プールの各項目は配布ファイルと `asset-pool.json` を持つディレクトリ。記録形式はスキーマ1で、元ファイル名、配布名、完全な SHA-256、バイト数、元参照、コミット OID、任意の HTTPS URL と利用者メモを含む。空ファイルにもバイト数0の明記が必要。配布名の16桁の短縮ハッシュは表示用。フォルダー名には記録全体の SHA-256 を含め、同名・異内容と同一内容の異なる使用記録を区別する。収集が競合したときは公開済みの記録と内容を照合する。一致する既存項目は再利用し、破損または異なる項目を上書きしない。

Windows で所有ファイルを一時ディレクトリに書き込み、ディスクへの flush と読み戻しによる照合を終えてから、同じ親でディレクトリを置換なしで公開する。NTFS では子のハンドルを開いたまま親を改名できなかったため、子を閉じてから、予約した親の物理 ID を照合して改名する。公開後はトークン取消の有無に関わらず記録とペイロードを再検証する。失敗時は所有を照合できたファイルと空のステージだけを削除する。共有切断などで掃除できない場合はステージを保持する。再試行では完成済みの同一項目を再利用できる。ストレージ障害や電源断時の永続性は未検証。

保存先は操作ごとに指定できる。別ドライブと UNC の通常パスを受け取れるが、ディレクトリと通常ファイルの保護、物理 ID 照合、同じ親での上書きなしの改名を利用できる共有先に限る。実 NAS と SMB 実装間の互換性は NOT_VERIFIED。合成の共有切断は公開直前に I/O 例外を注入し、元ファイルが残り、再試行で完了することを確認した。

## 受信側の照合

1. 受信 PF は明示的に選択して読む。記録された `FilePath` は候補探索には使わず、元ファイル名だけを文字列として取り出す。
2. 元ファイル名と独立に確認済みの SHA-256 を使用する。ハッシュ未記録なら候補は提示しない。ハッシュのみ、名前のみ、短縮ハッシュでは採用しない。
3. 指定した検索フォルダーの直下の同名ファイルと、同フォルダーの該当するプール項目を確認する。入手した記録を指定する場合は、許可範囲内の `asset-pool.json` を選ぶ。大文字と小文字を区別するフォルダーに対応するため、許可した範囲は大小文字も含めて照合する。ドライブまたは通常のUNCのみを使用し、デバイス名前空間や再解析ポイントは拒否する。ペイロードのファイル名は配布名に限定し、パスや URL を解決しない。
4. 候補が複数なら、利用者が特定の候補を選ぶ。適用直前に、直前の候補と記録のハッシュ・名前・サイズを再確認する。検証リースはディレクトリ、候補、記録を保持し、再リンク保存までの変更を拒否する。
5. 受信側でコピーやダウンロードは行わない。再リンク出力は既存の SaveAs を通じて別名を使う。

素材プール記録はメタデータの搬送に使えるが、受信 PF やプール記録の申告だけで期待ハッシュを確定しない。既存の手動管理付き再リンクは別操作として維持し、厳格な照合結果に含めない。

## 重点試験

隔離した Windows/NTFS と合成ファイルを使用。Release・Debug で各12件成功。実 NAS、実 YMM4 での読込、受信後の現場向けの受入は未実施。

収集と元保全、同名異内容、異名同内容、並行収集と再利用、改変済み項目の上書き拒否、明示候補と検証リース、未許可先とジャンクション、記録の改変・パストラバーサル・重複キー、空ファイルに対するサイズ欠落の拒否、デバイス名前空間と大小文字が一致しない記録パスの拒否、取消・合成 NAS 切断後の再試行、受信 PF の参照非探索、新規 PF への限定した置換を確認した。
