## 保存・復旧時の操作

- 保存記録を一覧画面から確認する。後継がある下書きと曖昧な下書きは別ファイルへの退避だけを選べる。閉じた記録も同様。系列のファイルを個別に移動・削除すると、後続が存在した証拠を失うことがある。
- 「一覧の ID を確認・修復」は、同じ物理ファイルを確認できたグループごとに残す登録を指定する。現用一覧へ反映するときは原本を新規ファイルへ退避する。判断に必要な関連付け・リンクが他の行に残っている場合は先に原本を保全する。
- ファイルの再リンクは新しい `.ymmp` に保存する。中断した場合は「再リンクの回復」で `.ymmpm-relink-*.json` を選ぶ。出力の新規公開を伴う可能性を確認してから進む。同じディレクトリの `.publish` と `.output.tmp` は対応する回復証拠。既存出力は上書きしない。記録が破損・欠落している場合は元、出力、候補、履歴を保全する。

## 検証方法

隔離コピーした YMM4 参照 DLL を `YMM4_PATH` に指定する。並行起動では Windows 上の短い専用一時フォルダーをプロセスごとに用意し、`TEMP` と `TMP` を設定する。`YMMPX_LIB_PATH` は実 DLL ありの回だけ隔離した DLL を指定する。Git はローカルの bare remote を利用する。

```powershell
dotnet build .\YMMProjectManager.sln -c Release "-p:YMM4_PATH=$env:YMM4_PATH" --nologo
dotnet build .\YMMProjectManager.sln -c Debug "-p:YMM4_PATH=$env:YMM4_PATH" --nologo
dotnet run --project .\YMMProjectManager.Tests -c Release --no-build
dotnet run --project .\YMMProjectManager.Tests -c Debug --no-build
$env:YMM_TEST_FILTER = 'AssetManifestTests,RealYmmpxR5,ProjectListPublicationTests,ProjectListIdentityRecoveryTests,ProjectListSaveTests,OfflineControlsTests'
dotnet run --project .\YMMProjectManager.Tests -c Release --no-build
```

両ビルドとも終了コード0、警告・エラー各0。個別名を付けていない従来ケースは、個別件数に含まれない。子プロセスを終了させた検証は、下書きと再リンク出力の公開前後を合成データで確認する。電源断やホストの異常停止は対象外。

## リリースを止める残件と再開地点

1. **P0 Git Pull**。書き込みは無効。読み取り専用の表示は設定済み追跡 ref、index、未完了操作を確認する。同じ tree の fast-forward でも、files と reftable の両方でシンボリック HEAD の検証と参照先 CAS を同じトランザクションに入れると拒否された。 `GitRepository.PullAsync` を起点に、非協調 Git とファイル編集も含む排他・回復の実証が必要。 [Pull の実験と契約](../architecture/adr/git-pull-recovery-r16.md)
2. **P0 非協調プロセスによる一覧置換**。照合から公開までの直接書き込みは共有モードで抑止した。NTFS 上で名前置換は引き続き可能だった。削除共有を拒むと自分の置換も止まり、バックアップ指定は押し出す内容を保全するが現用ファイルの上書き自体は防がない。`JsonProjectRepository.SaveCoreAsync` から、相手の版と同じ場合に限り公開できる契約を検証する。確認から置換までの間に別版が入れば拒否し、両版を回復できる試験が必要。
3. **未受入**。読み取れないファイルの識別、旧 YMMPX、GitHub 実認証、実 YMM4 は実条件の試験が残る。世代 Manifest の非協調プロセスとの競合や電源断は R15 の制約を引き継ぐ。視覚的なプロジェクト差分と旧チェックポイントの復活は実装していない。アクティブタイムライン反映は **STRETCH_GOAL / DISABLED**。この項目単独でリリースを止めない。
