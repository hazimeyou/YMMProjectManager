## 外部素材を使った出力とIdentity

同じIdentityに出力を移す方式では、R21の管理再リンクと同様に一覧の主登録が出力へ移り、元PFはバックアップの位置付けになる。R22は元PFを別に開いて履歴も追えることを優先し、外部素材を使う出力には独立した派生IDと別のメタデータ系列を用いる。元の一覧項目、物理ファイルID、既存の系列と全履歴は維持する。派生元のプロジェクトID、ルート、選んだ版とダイジェストを記録する。既存の内部素材用移行は変更しない。

元ファイル名と完全SHA-256が両方一致する候補だけを扱う。プールの配布名は、記録に含まれる元ファイル名と対応付け、選択した系列の期待値を別に照合する。初回と回復時は許可されたフォルダー内の候補だけを開く。受信PFに残るパスや保存済みの日本語・UNCパスは、利用者が再指定するまで外部ファイルを開く根拠にしない。素材の自動取得・コピー・配布は行わない。

外部素材の出力は、元PFと同じフォルダーの別名ファイルに限定する。出力の内容と物理ファイルIDを記録し、所有ハンドルと非上書き公開を再利用する。派生履歴を確定し、出力を公開してから、一覧を比較保存する。各段階が別々に失敗し得るため、記録を残して利用者に回復操作を案内する。派生追加を通常の一覧下書きに載せると素材の再承認を迂回できるため、一覧は別のスナップショットに対して比較保存する。専用の再リンク回復を経て、元の登録と派生行がディスクで確認できた場合は再書き込みなしで採用する。

## 互換性と保存境界

- 元PF、元素材、元プロジェクトの既存メタデータファイルを上書きしない。
- 既存の再リンク記録と元プロジェクトの登録形式を維持する。派生系列に追加した情報は旧版が解釈しない場合があるため、旧版向け書き換えは提供しない。
- Publish中断の結果が不明な場合、対象・作業ファイル・証拠を保持する。証拠がなく同名のファイルがある場合は引き継がない。
- Git の通常のロックやWindowsのハンドル共有に沿う競合を試験する。電源断・ファイルシステム障害の耐久性は別の受入項目。
- 専用回復では同じ正規化済みの検索ルートを再指定する。保管先を移した場合は、新しい承認を伴う再リンク操作を開始し、元の記録を保つ。

## 実環境の受入

1. **実YMM4・WPF**。承認済みの隔離ホストで、固定ビルドのPF整理後の読込、派生登録、元PFと派生PFの独立操作、回復を合成データで確認する。元PFを指す値がルートの `FilePath` に残る場合を含め、派生PFを開いて保存しても元PFのバイト列が保持されることを確認する。TLの本番Scene接続は現状を維持する。
2. **実GitHub**。許可を得た専用の公開・非公開リポジトリと試験アカウントで、保存済みGCM、権限不足、取消、Clone・Fetch・Pull・Pushを確認する。実資格情報の抽出やログ保存は行わない。
3. **実NAS**。専用共有で読み書き、同名衝突、切断、復帰後の再承認、別クライアントからの競合を確認する。共有やSMBの方針によってハンドルの共有・rename意味論が異なるため、それぞれの対象で受け入れる。
