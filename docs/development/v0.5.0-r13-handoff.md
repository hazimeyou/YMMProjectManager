## 実装の読み方

- **一覧** `Application/ProjectListMerge.cs` と `Infrastructure/JsonProjectRepository.cs`。一覧 JSON に任意の `MetadataAssociation`（場所、root・選択版・観測 head の ID と SHA-256）を追加。未設定の旧項目には書かない。未知項目のある一覧は書き込みを止めて原本を保護する。以前のプラグインからの書き込み互換性は未受入。切り戻し前に一覧原本を退避する。
- **保存記録** `Infrastructure/ProjectListDrafts.cs` と `Presentation/ViewModels/ProjectListDraftRecovery.cs`。一覧の隣に、BASE 版、BASE・LOCAL の一覧、追加対象の ID と SHA-256 を含む版 1 の記録を保存する。チェックサムで破損を検出する。`.draft.json` は明示選択して排他取得後に適用できる。`.saving` は保存が始まった記録で、再適用せず退避できる。`.closed` は履歴として保持する。
- **Identity と metadata** `ProjectListIdentity.cs`、`Infrastructure/AssetRevisionSeries.cs`。移動の確認は元が欠落した場合に限る。旧履歴インポートは完全な系列を新規フォルダーへ複製する。現行系列と旧原本は上書きしない。版の閲覧、選択、再関連付けは同じ一覧画面から行う。
- **素材と再リンク** `AssetInventory.cs`、`AssetRelinkRecovery.cs`、`RelinkMainWindow`。選択候補、元、出力、親版の証拠を保存し、照合できた場合だけ版を追加する。別名保存後に metadata が完了しなければ、元プロジェクトで「メタデータ更新を再開」から該当記録を選ぶ。既存版は再試行でも重複しない。出力への一覧の付け替えは手動設計が残る。
- **Git** `Infrastructure/GitRepository.cs`。ローカル remote で Git の構造化結果、対象 ref、取消を検証した。実 remote UI と Pull は停止。タイムアウトは一部サブプロセス単位。操作全体の予算、認証 helper の信頼、GitHub 接続は未完。
- **YMMPX** `Infrastructure/Packaging/YmmpxPackageReader.cs` と `YmmpxLibBridge.cs`。現行形式を管理コードで検証し、新規フォルダーへ公開する。既存フォルダーを上書きせず、自動でプロジェクトを開かない。未同梱参照はそのまま引き継ぐ。作成には YmmpxLib を使用する。

## ビルドと試験

Windows の隔離参照ディレクトリを `YMM4_PATH` と `YMM4DirPath` に設定し、`TEMP` と `TMP` を専用の一時領域に設定する。実ライブラリの試験時のみ、`YMMPX_LIB_PATH` を隔離済み `YmmpxLib.dll` に設定する。設定・プロジェクトはすべて合成 fixture。

```powershell
dotnet build .\YMMProjectManager.sln -c Release "-p:YMM4_PATH=$env:YMM4_PATH" --nologo
dotnet build .\YMMProjectManager.sln -c Debug "-p:YMM4_PATH=$env:YMM4_PATH" --nologo
dotnet run --project .\YMMProjectManager.Tests -c Release --no-build
dotnet run --project .\YMMProjectManager.Tests -c Debug --no-build
$env:YMM_TEST_FILTER = 'RealYmmpxR5'
dotnet run --project .\YMMProjectManager.Tests -c Release --no-build
```
