## Build と検証

Windows、.NET 10 SDK、WPF、隔離した YMM4 参照 DLL が必要。`TEMP`・`TMP`・`YMM4_PATH`・`YMM4DirPath` は専用隔離領域へ設定する。`CopyToYMM4` が build 時に `YMM4_PATH` 以下へ書くため、本番 YMM4 を指定しない。

```powershell
dotnet build .\YMMProjectManager.sln -c Release "-p:YMM4_PATH=$env:YMM4_PATH" --nologo
dotnet run --project .\YMMProjectManager.Tests\YMMProjectManager.Tests.csproj -c Release --no-build
```

実 YmmpxLib を使う場合は隔離コピーを `YMMPX_LIB_PATH` に指定して別 process で実行する。両条件で 56 top-level groups pass、0 fail、3 explicit skips。個別ケース数は未集計。Release build は warning 0 / error 0。実 DLL の直接展開は製品 bridge の成功ではない。

Debug build も exit 0、警告 0・エラー 0。Debug 構成のテストは未実施。

## 主な責務とレビュー順序

1. `Application/ProjectListMerge.cs` / `ProjectListRecovery.cs`: base・local・remote の保守的な統合、ID・path・順序・folder 参照の拒否条件。
2. `Infrastructure/JsonProjectRepository.cs`: snapshot revision、協調 lock、未知データ拒否、原子的な保存、no-overwrite recovery copy。`ProjectStore` を新規生成する外部呼出元は revision と `IsRecoverySafe` を引き継ぐ必要がある。
3. `Presentation/ViewModels/ProjectListViewModel.cs`: ユーザー確認、追加対象の hash 再検証、部分成功時の二つのメモリ snapshot と別名退避。一般的な restart recovery は未実装。
4. `Infrastructure/AssetRevisionSeries.cs` / `AssetManifestStore.cs`: 専用 directory の create-only revision と唯一 head 判定。旧 metadata の取込、UI・project list・relink への接続は未実装。
5. `Infrastructure/GitRepository.cs`: command-scoped 環境設定の遮断、Git 信頼境界。repo-local hook など通常設定は依然実行され得る。
6. `Infrastructure/Packaging/`: 新規 package の保護・最低限の構造検証。抽出 bridge は安全停止。
