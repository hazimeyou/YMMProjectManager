# R21 PF整理とYMMPX調査

指示 `YMMPM-R21-20261121` のPF担当。R20基準 `2789a5744e79e5941e36fc8eb0691aa125eccbf4` を使用した。YMM4の起動・設定変更・既存プロジェクトの読み込みは未実施。テストは隔離コピーした参照DLLと合成データを使用した。

## PFの調査結果

YMM4 `4.57.0.1+f7f1e4a691d0b476c5693586b4be2ce0c9b13a3c` の隔離参照DLLを静的に確認した。現在の `Project` モデルは複数の `Timelines`、選択中の `SelectedTimelineIndex`、`Characters`、`CollapsedGroups`、素材の基準となるルート `FilePath` を保持する。旧式の単数 `Timeline` は `Project.LoadOldTimeline` で移行する。YMM3の同拡張子形式はこの実装の対象外。公開履歴には複数の配布ビルドがあるため、整理を許可するモデルはこの参照ビルドに固定した。 [YMM4公式配布ページ](https://manjubox.net/ymm4/) · [4.57.0.1公式更新情報](https://manjubox.net/ymm4/release/4.57.0.1/)

`MainModel.LoadProjectFile` は `Json.Load<Project>` を呼ぶ。モデルの初期値は `LayoutXml` が空文字、`ToolStates` が null。プロジェクト読込後、`MainViewModel` は空レイアウトと null のツール状態で現在の環境の値に戻る。空の辞書は null と区別される。プラグインの `SerializableToolState.SavedState` は任意のJSONを文字列として保持できる。ツール状態の中身をファイル名や見た目だけで一時情報と判断できない。

| 分類 | PF項目 | 根拠・扱い |
|---|---|---|
| PRESERVE | タイムライン、Scene、アイテム、選択Timeline、編集状態 | プロジェクトの構造または選択に使われる。ルート以外の同名項目も含めて保持する。 |
| PRESERVE | ルート `FilePath`、素材参照、キャラクター、エフェクト | 素材解決や内容に関係する。他のフォルダーへの出力は同じ相対参照を保証できないため拒否する。 |
| SAFE_TO_REMOVE | 確認済みビルドの新形式ルートにある `LayoutXml: ""` と `ToolStates: null` | 現行モデルで省略時と同じ値になる。明示した既定値と省略を隔離参照DLLの実デシリアライザーで照合した。 |
| CONDITIONAL | 内容のある `LayoutXml`、空辞書を含む非null `ToolStates`、未確認ビルドや旧式PFの候補 | 読込時のレイアウトとツール復元に関係するため保持する。他バージョンとプラグインを含む実機受入が必要。 |
| UNKNOWN | 将来または未知のフィールド、未知のアプリ固有メタデータ、未同定のキャッシュや一時UI情報 | 削除しない。既知の候補と同名でも、ルート以外であれば保持する。 |

モデル単体検証では隔離DLLの `Json.LoadFromText<Project>` を呼び、`{"LayoutXml":"","ToolStates":null}` と `{}` の両プロパティ値が一致することを確認した。さらに `{"LayoutXml":"<layout/>","ToolStates":{}}` は空文字・nullと異なることを確認した。テストランタイムは .NET SDK 10.0.404 付属の Newtonsoft.Json 13.0.3 を用いた。YMM4本体の起動とプロジェクト読込全体の受入は **NOT_VERIFIED**。

## YMMPXとの関係

公開ソース `6cff832c4648f43708a7305935c6303b61319a9d`（v1.1.0）と、R20と一致する実DLL `1.1.0+6cff832c4648f43708a7305935c6303b61319a9d` を確認した。DLLのSHA-256は `107A522AAC5C0AAFD32494C0C93AC9404694FBA6A4BAD7902B78D0F000C2E552`。v0.3.0とv1.0.0のタグにも同じ2項目の除外APIが存在した。パッケージ作成では `IncludeProjectUiSettings` の既定値は true。false のとき `RemoveUiSettings` は内容によらずルートの `LayoutXml` と `ToolStates` を除外する。実DLLでネストした同名項目を保つことと、繰り返し適用時の挙動を確認した。 [YMMPX公開API](https://github.com/hazimeyou/YmmpxLib/blob/6cff832c4648f43708a7305935c6303b61319a9d/README.md) · [項目除外のソース](https://github.com/hazimeyou/YmmpxLib/blob/6cff832c4648f43708a7305935c6303b61319a9d/YMMPXLib/YmmpxProjectJson.cs#L17-L24)

YMMPXはPFから `FilePath` を走査し、パッケージに含めた参照を `resources/` に対応付ける。現行パッケージは .ymmp、`_ymmpx_project_path.txt`、`links.json`、素材本体で構成される。元PFの同じ場所に整理済みコピーを出す本機能は、その素材変換と展開を実行しない。既存ブリッジの `IncludeProjectUiSettings=true` と出力検証を維持する。旧パッケージの読込可否と、YMMPX自身の除外オプションを単独PFへ適用する互換性は別扱い。 [パッケージ作成のソース](https://github.com/hazimeyou/YmmpxLib/blob/6cff832c4648f43708a7305935c6303b61319a9d/YMMPXLib/YmmpxPackageService.cs#L129-L145)

## 実装

`ProjectFileCleanupService` は選択したUTF-8の .ymmp を読み、削除候補と理由を返す。旧式、ルートにシリアライザーの `$` 項目がある形式、未確認ビルドでは候補を保持する。JSON重複やタイムライン構造不正は拒否する。対象と判定したルート項目と必要な区切りだけをバイト範囲で切り取り、残りの項目名、値、数値の表記、エスケープ、UTF-8 BOMを維持する。

明示保存時には元ファイルの物理IDとSHA-256を再確認し、ファイルを読み取り共有で保持する。別名は同じフォルダーのみに限定する。専用の一時ファイルへ書き、ハッシュ検証後、開いたハンドルから上書き禁止で公開する。公開後には取消によって失敗扱いに切り替えない。元PFや外部素材への書き込みとGit操作はない。

## 試験と未検証

Release・Debugとも警告0、エラー0。隔離した実YmmpxLibありで各7件成功、失敗0。元SHA-256の保持、4種のルート位置とBOM、未知フィールド・相対素材参照・Timeline・Scene・エフェクト・メタデータ保全、再実行時の安定性、非対応ビルドと旧式の保持を確認した。不正JSON・不正UTF-8・重複の拒否、確認後の変更と同一バイトの物理ファイル置換の拒否、公開直前の競合と取消、一時ファイルの後始末を検証した。両構成とも別ハーネスで実YMM4デシリアライザーのモデル単体照合に成功した。

登録後は `YMM_TEST_FILTER=ProjectFileCleanupTests` で対象を実行できる。実YmmpxLib指定なしではAPI確認1件を条件付きスキップする。WindowsローカルNTFSの試験結果。YMM4実機、他のYMM4配布ビルド、未知プラグインの状態、省略対象を増やすこと、共有ファイルシステムでの公開は未検証。
