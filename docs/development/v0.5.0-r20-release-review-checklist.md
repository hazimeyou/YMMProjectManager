## Git と WPF の受入

| 判定欄 | 必要な証拠 |
| --- | --- |
| 承認・更新先 | 同一リポジトリとブランチの接続承認、更新先承認、承認済みコミットへの fast-forward、対象や upstream 変更時の拒否。 |
| 中断・復旧 | 実際に中断に到達した地点を記録し、HEAD、index、作業ファイル、未追跡・ignored の保全、回復記録の内容と再実行抑止を照合する。観測不能な結果は UNKNOWN として取り扱う。 |
| HTTPS | 検証用エンドポイント、TLS の信頼と名前照合、接続成功・失敗、更新先の移動・削除を個別に記録する。隔離 HTTPS の成功と、実ネットワークや認証必須 HTTPS の受入を別々に判定する。 |
| UI | 合成 ViewModel と実 YMM4 を別判定にする。実機では操作対象の表示、承認、取消、状態表示、回復記録の場所、操作中の応答を確認する。 |
| 対応制約 | 直接 checkout、固定ローカル NTFS、検証済み Git 設定。認証必須 HTTPS、linked worktree、任意の外部書き込みとの原子性、電源断を含む条件は個別の証拠を要する。 |

結果不明の Pull は、対象 checkout と回復記録を保全し、アプリ外の作業も含め最新のブランチ、HEAD、index、作業ファイルを確認する。新しい操作を行う前に利用者の変更を別の場所へ保全し、旧状態との照合結果を記録する。回復記録は照合と明示判断が済むまで保持する。 [R19 回復の設計と証拠](v0.5.0-r19-handoff.md)
