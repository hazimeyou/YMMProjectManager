## 試験定義の申請順序

1. [R15一次証跡と管理契約](v0.5.0-r34-manager-evidence.md) で基準を照合する。
2. 現存するR16のYMMPM定義は旧ソースと旧DLLのピンを持つ。管理側でR34の完全HEADとRelease DLL SHA-256を照合し、新規定義として受理できるかを審査する。旧定義、固定ピン、または今回対象外の管理機構を上書きする操作は本依頼の対象外。
3. 受理後、候補・環境・操作と回数の個別承認を経る。管理側が新規の隔離ステージへ審査済み候補を配置し、現物と配置先を再照合する。開始直前の隔離とRecoveryを確認してA01を実行する。A01の結果と、B〜Iの操作に必要な機能別の契約を根拠に独立実行の可否を決める。
