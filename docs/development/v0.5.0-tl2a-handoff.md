# v0.5.0 TL-2A 引継ぎ

TL-1R と TL-2A は COMPLETE。TL-2B は実機未着手。v0.5.0 のリリース判定は現行のまま。

再開点は `codex/ymmpm-v050-tl2a-scene-integration` の検証済みコミット。起点の TL-1 は `793ebf354e755ca7cd862b8d9301885a2d0a717b`。 `SceneComparisonPlan.Prepare / CheckObserved / Compare` が値の受け渡しを定義し、`SceneCapturedFrame.Copy` が見えている画素を独立所有する。製品からの呼び出しは登録していない。

## TL-2B の開始と受入

1. 共有基盤の存在と起動権限を区別し、正式に許可された隔離 YMM4、合成プロジェクト・素材、復元手順と事前ハッシュを用意する。TL-2A はホストの起動許可や隔離成立を確認していない。
2. 同一プロジェクトの別 Scene で、非アクティブ Scene の owner・リビジョン・寿命を安全に取得できることを実証する。アクティブ切替や別プロジェクトの取り込みで準備しない。ホスト全体のプレビュー・書き出し・編集との非再入を確認する。
3. Scene A/B に別色と既知のフレーム番号を用意し、操作を別々に識別して A→B→A、逆順、先頭・中間・末尾・範囲外を検証する。A の再現と B の出所を確認する。異なる FPS の実フレーム照合を、SDK が描画した時刻の観測に基づいて試す。
4. 実 BitmapSource の形式、元色表現、寸法、stride、DPI の記録を取る。必要な色・alpha 変換、精度低下、透明画素の方針を定義し、試験してから接続を検討する。
5. アクティブ状態、選択、Undo/Redo、dirty、編集コマンド、既存プレビューを前後・失敗後に観測する。取消、ホスト終了、Scene 置換、同時要求、描画・解放故障を検証し、状態とプロジェクト・設定ハッシュを確認する。GPU、メモリ、UI 応答、解放漏れも測定する。

ホスト側の権限、観測可能性、排他、形式の四点が残る。試験はまず同一プロジェクトの逐次フレーム取得から。2 native panel、入れ子 Scene、別プロジェクトは個別の受入項目にする。
