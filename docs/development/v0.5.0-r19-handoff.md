## 操作と保護範囲

1. プロジェクトを選択して Pull を開始すると、ローカル checkout、作業ブランチ、設定されたリモートと上流ブランチを確定する。最初の画面で、その接続先を照会することを承認する。
2. リモートの現在のコミットを読み、2番目の画面でリポジトリ、ローカルと上流ブランチ、接続先、旧・新コミットを表示する。既定ボタンはキャンセル。実行中の外部操作を控える旨を同じ画面に表示する。
3. 実行時に承認済み状態とリモートを照合し、承認済みのオブジェクトを取り込む。追跡 ref と `FETCH_HEAD` は変更しない。追跡情報を更新する既存の操作は Fetch。変更前に branch、HEAD、index、作業ツリー、進行中の Git 操作、対象ツリーの Windows パスを検査する。
4. Git の `merge --ff-only --no-autostash --no-overwrite-ignore` に完全な OID を渡し、Git の終了と branch・HEAD、index、作業ツリーの一致を確認する。同一アプリプロセスからの Git 更新はゲートで抑止する。ネイティブ実行後に取消要求が届いた場合は検証を完了して結果を表示する。
5. 結果を確定できなかった場合は `.git/ymmpm-pull-in-progress.json` を保持し、次の Pull を止める。ファイルと記録を保全し、Git で現在の branch と HEAD、index と worktree の状況を確認する。外部 Git が処理中でないことも確認する。受入時は隔離コピー上で状態を照合し、復旧の根拠を決定した後で記録を別名で保管する。自動 reset、自動 stash、盲目的な再試行はしない。

固定ローカル NTFS 上の通常の直接 checkout と、単一の明示上流を対象とする。リモートは固定ローカル NTFS のディレクトリまたはリダイレクト・認証プロンプトを必要としない直接 HTTPS。実測したのはローカル bare remote。認証を要する HTTPS、プロキシ、linked worktree、shallow や一部の特殊設定、外部フィルター、有効な署名検証ポリシーなどは安全に実行できないため拒否する。古い無承認 `PullAsync` は拒否を維持する。通常の Clone・Fetch・Push は従来の接続契約を維持した。

ネットワーク側の変更は明示の再観測で検出する。Git やエディタを含む任意の外部プロセスを排他する契約はない。規定の検査の間に同じ状態へ戻る外部変更は観測できない場合がある。作業ツリー更新前の取消でも Fetch したオブジェクトは残り得る。電源断や、プロセスが native Git の更新途中で強制終了した場合の復旧は実環境で未検証。

## 受入の記録

| 条件 | 隔離試験で確認した結果 |
|---|---|
| 正常更新、同じ版、日本語パス | 承認済み branch と HEAD。index と対象 tree、作業ファイルを照合。最新の場合は更新せずに状態を確認。 |
| 分岐、上流未設定、リモートの先端移動・削除 | 更新を拒否。旧版と作業ファイルを保持。 |
| dirty、staged、untracked・ignored の衝突 | 既存ユーザーファイルを保持。Windows が1ファイルへ折り畳む大文字・小文字の衝突も更新前に拒否。 |
| 既存 Git ロック・参照変更・外部 branch 切り替え | 開始前に条件が変われば拒否。別 branch が動いた場合は不明な結果として証拠を保持。実 ref が共有で拒否される条件も検証。 |
| app-owned 並行実行 | 同一プロセスからの同時 Git 書き込みを拒否。単独の Pull を有効にする記録名も競合時に上書きしない。 |
| 取消・準備 timeout・プロセス再開 | 更新前取消と準備 timeout は HEAD・index・worktree を保持。Git 起動後の取消は結果確認まで待機。操作記録を書いた直後と、native Git 更新後の事後照合前、両方でテスト子プロセスを終了した。再起動後は結果を不明として記録を保全し、再実行を拒否。 |
| 設定・パス・権限 | 読取不能な設定、linked worktree、許可できない設定、Windows パス競合、予約名・reparse の一部を拒否。UNC は構文単体で検証し接続していない。 |

独立確認は、初期コードで正常 Pull が graft の助言により拒否されることを製品 API で再現し、修正後に隔離 bare remote の Pull、Unicode ファイル、リモート先端の移動・削除、再起動後の回復記録を再検証した。最後の差分レビューでは新たな P0/P1 を確認しなかった。WPF 試験は ViewModel の合成承認と実 Git による更新を組み合わせ、実 YMM4 の操作は含まない。

フィルターの最終レビューでは属性値が特別な表示文字列と同じになる条件と出力長の上限を確認した。文字列 `unspecified` のドライバーを含む合成 tree で拒否を確認した。フィルターを明示的に解除した属性も保守的に拒否する。8,388,608 UTF-16 コード単位を超える tree・属性出力では照合を中止する。

## 再実行

隔離した YMM4 参照 DLL を `YMM4_PATH` に指定し、テストプロセスごとに別の短い `TEMP` と `TMP` を使う。実 DLL ありの回だけ `YMMPX_LIB_PATH` に隔離した実 YmmpxLib を指定する。

```powershell
dotnet build .\YMMProjectManager.sln -c Release "-p:YMM4_PATH=$env:YMM4_PATH" --nologo
dotnet build .\YMMProjectManager.sln -c Debug "-p:YMM4_PATH=$env:YMM4_PATH" --nologo
dotnet run --project .\YMMProjectManager.Tests -c Release --no-build
dotnet run --project .\YMMProjectManager.Tests -c Debug --no-build
$env:YMM_TEST_FILTER = 'GitRemoteTests,GitPullRecoveryTests,OfflineControlsTests'
dotnet run --project .\YMMProjectManager.Tests -c Release --no-build
```

全回帰は `YMM_TEST_FILTER` を設定しない。個別計測数は明示的に計測されたテストだけを集計する。旧形式 YMMPX の真正な fixture は未提供。実 GitHub の認証、実 WPF ダイアログ操作とライブタイムラインは別の隔離受入で確認する。

Release と Debug の MSBuild は終了コード、警告、エラー各0。実行時間は2.30秒、3.06秒。基準の62グループ・個別93件から、各構成の個別計測が27件増えた。書き込み Pull の明示スキップは解消。実 DLL なしの1件は外部 DLL を意図して指定しない構成の条件分岐。全4構成で合成 Git と WPF、外部素材、一覧、再リンク、メタデータ、YMMPX の既存回帰を実行した。

## 再開点

`GitRepository.ConfirmedPull.cs`、`GitConfirmedPullTests.cs`、WPF の `ProjectListGitPullWorkflow.cs` から再開する。先に実用 HTTPS を隔離して、認証を求めない接続の受入と、認証を使う場合の契約を確認する。次に実 YMM4 上で、2段階承認・取消・不明結果の表示をテストする。最後に native Git の更新途中での制御されたプロセス中断を専用 fixture で検証し、現用 branch・index・ファイルを比較する。

残る受入には、隔離 HTTPS、使用を許可された YMM4 環境、native 子プロセスの更新途中を制御できる専用障害注入の準備が必要。実環境を使わず安全に確認できた Checkout 前・更新直後の失敗と再開は完了した。1回のビルド・回帰で区切らず、独立レビュー後の修正を含む最終コードで4構成を再実行して引き継いだ。
