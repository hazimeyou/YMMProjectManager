# v0.5.0 TL-1 Scene 接続条件

**ホスト接続は未検証。** TL-1 が受け取るのは、不透明な値によるソース識別、時刻・フレーム情報、バッファのみ。Scene 解決、描画、パネル、アクティブタイムラインの再リンクへの経路は追加していない。次の要件は PM 側の接続条件であり、YMM4 SDK の保証を表すものではない。

## YMMPrint の引継ぎ

YMMPrint の `ef6a93b8099b92afe7172012abb0ea6c35daecd2` で記録された `docs/research/tl-preview-pm-handoff.md` と `docs/research/tl-preview-test-results.md` を読み取り確認した。R1 は候補経路 `Scene.TryCreateVideoSource` → `Update` → `RenderBitmapSource` の公開型確認・ビルドと、A→B→A の合成試験を実施。2 Scene / 2 native panel の実機動作、非アクティブ Scene、ホスト全体の編集状態・描画排他は受入未実施。同期 SDK 呼び出し中の中断契約も未確認。

## 接続時の検査

1. **識別と寿命**。ホストインスタンスとセッション、プロジェクトとリビジョン、所有 Scene と Timeline の文脈、参照の寿命を権威あるホスト情報に基づいて結び付ける。Scene GUID 単体で対応付けず、スナップショット ID をこの束縛に対して発行する。A/B が別の実体かホスト側で確認する。プロジェクト切替、再読込、編集、Scene 置換、ホスト終了で古くなった束縛は失効させる。
2. **描画条件**。共通の論理原点と各 Scene の FPS・フレーム範囲を検証し、選ばれた0始まりフレームに対するホスト時刻を SDK に即して求める。解像度、背景、画質、色空間・alpha、エフェクトやアニメーションの評価条件を双方で宣言し、同じ契約に対応する設定 ID を使う。未確定の条件が双方で同じ文字列というだけでは互換と扱わない。異なる FPS で SDK が選択フレームを描いたと判定できるかは要受入。
3. **有効性と実行制約**。描画直前、処理中の適切な箇所、コピー後およびペア公開前に、実体・リビジョン・寿命・フレーム・出力条件の一致を確認する。不正・失効した参照からの結果は返さず、ホスト側の失効や失敗として扱う。実行スレッド、キャンセル可能な箇所、ホスト全体の描画・書き出しとの排他を実証する。共有資源の解放責任と借用参照の有効期間を確認し、期間外に参照を保持しない。
4. **引き渡し**。借用した画素を寿命内に独立コピーし、実際のフレーム情報とともに渡す。変換が必要な場合は別の明示的処理とし、元形式、変換方法、精度低下を確認する。YMMPrint R1 の変換試験では半透明 Pbgra32 の straight 変換で1 LSBの丸め例がある。ホストの編集状態が変化した場合は失敗として扱い、位置復元などの編集操作を自動で行わない。
5. **利用**。比較結果の表示とホスト障害の表示は将来の呼び出し側が担当する。比較値が示すのは供給されたフレームの画素差。再リンクの検証では素材の参照先・存在・必要に応じた内容照合と、プロジェクト構造の確認も必要。通常の診断にはファイルパスや画素を含めず、保存・送信は別の製品要件で決める。

## TL-2 の作業候補と受入条件

隔離済みの YMM4 と合成素材で、まず同一プロジェクト内の別 Scene を対象に、読み取り専用のスナップショット束縛と描画の成立を検証する。既知の色とフレーム番号を入れた素材で A→B→A、逆順、先頭・中間・末尾、欠落素材、非アクティブ Scene、取り消し・終了・失効、同時描画要求を確認する。描画と書き出しの排他、正しいリソースの解決と解放を検証する。

アクティブ Scene、シーク位置、選択・スクロール・ズーム、Undo、dirty flag、プロジェクト・設定の状態を前後で確認する。別プロジェクト由来や入れ子 Scene、2 native panel の同時表示と操作独立性は、それぞれ別の実機受入項目とする。TL-1 による v0.5.0 のリリース判定の変更はない。
