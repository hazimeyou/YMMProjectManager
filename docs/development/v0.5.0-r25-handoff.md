# v0.5.0 R25 開発引き継ぎ

対象は `hazimeyou/YMMProjectManager`。R24までの統合、Codexによる機能別整理、ユーザー専用ブランチの3つの復帰地点を設けた。v0.5.0 の実GitHub・実YMM4受入は継続する。

## 復帰地点と履歴

| 用途 | ブランチ | 基準 |
|---|---|---|
| 正式版 | `master` | `bdf6dbd32c910bd2a9ea6432399ba40f8f1d72af` |
| リファクタリング前 | `codex/ymmpm-v050-integration` | `2aaf11b3478681044436848c1c46fd772f58e232` |
| Codexによる整理後 | `codex/ymmpm-v050-refactoring` | 試験済みコード `398d09a0bbf46044400566dec3abdac57577f314` に文書のみを追加した先端 |
| ユーザー用 | `hazimeyou/ymmpm-v050-refactoring` | 引渡し時は上段と同じコミット。ここから独自に変更できる |

R19〜R24、TL-2B、過去の統合 `integration/ymmpm-v0.5` はR24先端の祖先だった。R21 Git担当の4つのコミットは統合側に調整済みの対応版がある。公開レビュー用PR #4のR11スナップショットは旧統合版と実装・テストが一致し、文書のみ異なる。統合基準は追加のマージを要しなかった。R24で試験した `c34255a` から統合基準までの7ファイルも文書のみ。既存worktreeにある独立した作業はそのまま保全した。

ユーザー調整は空の作業場所から始められる。取得後、最初の2行で引き渡し時点の先端を照合できる。ユーザーが独自にコミットした後は両方の値が異なってよい。

```powershell
git fetch origin
git rev-parse origin/codex/ymmpm-v050-refactoring origin/hazimeyou/ymmpm-v050-refactoring
git worktree add ../YMMProjectManager-user hazimeyou/ymmpm-v050-refactoring
```

基準との比較には `git diff --find-renames codex/ymmpm-v050-integration..codex/ymmpm-v050-refactoring` を使う。古い設計資料のソース位置はその資料が対象としたコミットで参照する。

## 再試験

Windows x64、.NET SDK 10.0.404、Windows Desktop Runtime 10.0.15。YMM4 4.57.0.1の隔離参照DLLを構成別に複製した。テストごとに新しい一時ディレクトリを割り当てた。ReleaseとDebugの実YmmpxLibありでは1.1.0のSHA-256 `107A522AAC5C0AAFD32494C0C93AC9404694FBA6A4BAD7902B78D0F000C2E552` を照合した。旧パッケージはR23で公開版 v0.2.1 / v0.3.0 / v1.0.1 から生成した合成PFのfixtureを使用した。

以下は構成1件分の実行例。`$isolatedRefs` は対象構成専用の参照DLLのディレクトリであり、ビルド後にプラグインDLLがコピーされる。`$isolatedTemp` は実行ごとに準備し、`$artifacts` は同じHEADのビルドと実行で共用する。`$releasedFixtures` には版別の `sample.ymmpx` を用意する。実ライブラリなしの構成では環境変数を解除し、隣接ディレクトリに自動発見対象のライブラリがない場所で実行する。

```powershell
$env:YMM4_PATH = $env:YMM4DirPath = $isolatedRefs
$env:TEMP = $env:TMP = $isolatedTemp
$env:YMM_TEST_YMMPX_RELEASED_FIXTURES = $releasedFixtures
$env:YMM_TEST_FILTER = $null
$env:YMMPX_LIB_PATH = $realLibraryOrNull
$env:PathMap = (Get-Location).Path + '=/_/src,' + $artifacts + '=/_/build'
dotnet build YMMProjectManager.sln -c $config '-p:Version=0.5.0' --artifacts-path $artifacts --nologo
dotnet run --project YMMProjectManager.Tests -c $config --artifacts-path $artifacts --no-build
```

`$config` はReleaseとDebug。隔離HTTPSは `YMM_TEST_FILTER=GitHttpsAcceptanceTests` を指定して別枠で実行した。統合基準の初回はfixtureの配置漏れで4構成とも個別234件・6件スキップになった。旧3版と実DLLの配置・ハッシュを確認して4構成すべてを再実行し、比較には再実行の値を使った。実ライブラリなしで意図した3件のスキップは実ライブラリ試験、PF整理比較、YMMPX 1.1 API読込である。個別件数はランナーが計測したものに限られ、未計測の入れ子チェックは含まない。

## 独立レビュー・既知の制約

- 履歴・設計担当はR24と最終コードのC#宣言をRoslynで照合し、素材ハッシュ、5つのGit操作の対応、WPF部分クラスのフィールド初期化、承認と再検証の順序を確認した。設計例に対するP3は修正後に再確認した。
- 互換性担当はDLLのメタデータを読み、公開・protectedの署名等を正規化した2,876行が一致することを確認した。公開155型、メソッド1,896、プロパティ724、フィールド87、イベント10。リフレクション対象の `TimelineContextService` とgetterも維持した。WPFリソース8キーと `YMMProjectManager.g.resources` のSHA-256 `97E8FAE3FAB64AF511F8540ACB3C6D362C4A0262AA4166A7C8F962A32BED8D32` が一致した。
- 公開前検査担当は、R24までの319コミット、1,333個の一意なblobと、新しい3つのコードコミットの差分を検査した。新規22 blobに既知の素材・パッケージ・秘密情報の検出なし。過去のYMM4参照DLLやテスト生成物は既にmasterの履歴に存在する。拡張子・署名・資格情報パターンの検査には検出限界がある。
- 独立担当による確認はソース・履歴・生成DLLの比較である。製品のビルドと回帰試験はControllerが実行した。
- 新規の未解決P0/P1はレビュー範囲で0件。既知のP2にGCMの複数アカウント選択と過去のバイナリの到達性、既知のP3に対応GCM版の再検証がある。実GitHubの初回・再ログイン、公開/非公開リポジトリ、実YMM4の導入・読込・復旧は別の受入ゲート。TL本番Scene接続は引き続き無効。
