# R32 D09のホスト接続調査

## 基準

PMはR30の `1cea4d91949845f46dc1fd4f10c11ac5be9d3591` を基準とした。参照元は [YMMPrint main 7e0284a](https://github.com/hazimeyou/YMMPrint/tree/7e0284a162794d099d674b6f3c0f92e333356931) と [YMMPrint R2 5140548](https://github.com/hazimeyou/YMMPrint/tree/5140548669b5d136802d967875ca18c2da6333ce)。参考リポジトリを編集せず、YMM4の起動、プラグイン導入、共有VMへの接続は行っていない。

## D09-1 タイムライン素材再リンク

[PM v0.2.0](https://github.com/hazimeyou/YMMProjectManager/tree/34e08b368dfaf6cbe7450a7d6ea97df0f59ed691) と [PM v0.3.0](https://github.com/hazimeyou/YMMProjectManager/tree/fd4fdbac03205461d3e1135a77d0fc6ecc7a97de) の `Infrastructure/Relink/TimelineMediaRelinkService.cs` は、検査時のアイテム参照を保持し、保存時に画像・動画・音声の `FilePath` を順に変更する。反映後に `UndoRedoManager?.Record()` を一度呼ぶ。v0.3.0の単一アイテム経路も、ファイル選択ダイアログを閉じた後に当初の参照を書き換える。旧経路には、反映直前のowner・対象寿命の照合や、一部変更後にsetterまたはRecordが失敗した場合の復元契約がない。

現行の停止点は [保存処理](../../YMMProjectManager/Relinking/TimelineMediaRelinkService.cs#L111) と [ウィンドウの保存入口](../../YMMProjectManager/Presentation/Relink/RelinkMainWindow.xaml.cs#L272)。開いているタイムラインの候補検査は実行できるが、書込みは拒否する。4.57.0.1の参照DLLのメタデータには物理的なタイムライン操作とUndo/Redoの公開APIがある。複数setterの一括反映、Recordの履歴境界、失敗時の状態の意味は公開メソッド名から確定できない。

**BLOCKED。** 当面は選択PFを対象に厳格な照合・別名保存を利用できる。再開には、隔離ホストで同一名PFの差し替え、選択・Scene変更、別アイテムの未保存編集、複数変更間の失敗、Undo／Redo各1回の差分を独立に観測し、対象外の変更が残ることを確認する。

## D09-2 シークを行わないサムネイル

YMMPrintの [PreviewTool](https://github.com/hazimeyou/YMMPrint/blob/7e0284a162794d099d674b6f3c0f92e333356931/ToolProbe/PreviewTool.cs) は、既存のホスト文脈でTimeline IDからSceneを取得する。`Scene.TryCreateVideoSource`、`Update(FrameTime.Time, Paused)`、`RenderBitmapSource` を順に使い、所有するsourceを解放する。[PreviewImage](https://github.com/hazimeyou/YMMPrint/blob/7e0284a162794d099d674b6f3c0f92e333356931/ToolProbe/PreviewImage.cs) は画素を独立コピーして凍結し、[FrameSelection](https://github.com/hazimeyou/YMMPrint/blob/7e0284a162794d099d674b6f3c0f92e333356931/ToolProbe/FrameSelection.cs) は0以上・長さ未満を検査する。参照元はMITライセンス。描画の寿命とコピーの考え方を参照し、ソースを移植していない。

| 方式 | 結果 |
|---|---|
| 既存プレビューをシーク | 現行コードは読込み時のPF実体・版を証明できずに停止する。タイムラインのシーク位置を変更しない要件にも適さない |
| 開いているSceneからVideoSourceを生成 | 指定フレームのSDK入口は確認済み。保存済みPFと編集モデルの同一性、GPUや共有設定、既存プレビューとの状態分離、取得画素が要求フレームかを独立確認する手段は実機未受入 |
| 選択PFの確定バイト列から別Sceneを構築 | 本番の第一候補。4.57.0.1の参照DLLにProject、Scenes、Scene型はある。プロジェクトファイルを既存ホストから隔離して読み込み、相対参照・プラグイン・素材設定を解決する契約は確立できていない |
| 別の隔離ホスト・プロセスで描画 | 現在のエディターへの影響範囲を分けられる可能性がある。ファイル、ユーザー設定、IPC、素材アクセス、停止・復旧の境界とGPU受入が必要 |

R32では [独立描画源を受ける生成処理](../../YMMProjectManager/Thumbnails/SeekPreviewThumbnailGenerator.Detached.cs) を追加した。PFの読取りハンドルを保持し、独立した描画源が報告する物理IDと完全SHA-256を照合する。最初と最後を含む64スロットを動画長から計算し、短い動画で同じフレームを再描画しない。観測フレームが違う、選択・描画源が変わる、取消、解放が失敗する場合は完了キャッシュの公開を止める。物理IDと内容に基づくキー、既存の所有付きキャッシュ公開を使用する。描画源の入口は製品UIに登録していない。将来の接続では、正確な版に結び付いたキャッシュ表示経路も追加する。SDK解放失敗などでは同じホスト描画区間を隔離し、原因の確認前に再試行を許さない。

**部分完了。** Release・Debugのビルドは成功し各警告・エラー0件。4.57.0.1の隔離参照で `YMM_TEST_FILTER=PreviewComparisonTests,RelinkIntegrityTests` を実行し、各2グループ、個別26件成功、失敗・明示スキップ0。新規5件は、64点の選定、短尺の重複描画抑止、誤PF／誤フレーム、取消、選択失効と解放失敗、PF保全を合成描画源で確認する。SDKを使った実描画は未実施。再開条件と観測項目は [YMMPrint R2のPM引継ぎ](https://github.com/hazimeyou/YMMPrint/blob/5140548669b5d136802d967875ca18c2da6333ce/docs/research/tl-preview-r2-pm-handoff.md) と [既存のホスト観測表](v0.5.0-tl2b-state-observation.md) を参照する。
