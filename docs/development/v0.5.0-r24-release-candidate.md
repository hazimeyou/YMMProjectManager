## 候補の再作成と照合

1. 試験済み統合コードHEADを固定し、隔離参照DLLで `dotnet build .\YMMProjectManager.sln -c Release -p:Version=0.5.0 --nologo` を実行する。
2. 新規のステージングへ下表のファイルをコピーする。READMEは `readme.txt` に改名し、現行機能と説明の一致を点検する。R24ドライランは既存定義どおりPDBを含む。
3. ステージング直下のみをZIP化し、拡張子を `.ymme` にする。ルートのファイル名、件数、重複を確認する。新規ディレクトリへ展開し、各メンバーのSHA-256をステージング元と照合する。

## 承認済み隔離環境での受入

- [ ] **導入**。試験済みHEADと成果物のSHA-256を記録してから承認済み隔離YMM4へ導入する。再起動後に「ツール」から起動し、製品の版と一連の操作の可否を記録する。
- [ ] **更新・復旧**。旧版、一覧、Identity、メタデータ履歴、素材プールを隔離環境で退避する。更新後に合成PFの一覧・履歴・設定を比較する。失敗時はログと新旧状態を保持し、互換性が確認できたバックアップから隔離先を復旧する。
- [ ] **GitHub認証**。有効化済みの方式に限り、承認済み試験アカウントで初回ログイン、既定ブラウザ、取消、失効後の再ログイン、タイムアウト、保存済みGCMの再利用を確認する。無効の場合はその状態を記録する。資格情報の抽出や表示を伴わない。
- [ ] **Git境界**。許可された公開・非公開専用リポジトリでClone、Fetch、fast-forward Pull、非force Push、確認付きCommit、個別Stageと解除を確認する。認証とGit操作は独立で承認し、接続先変更時に再確認する。素材・YMMPX・回復記録を含む変更を拒否する。
- [ ] **YMMPX送受信**。合成PFを選び、素材ごとに許諾を設定して同梱・除外・不足を確認する。再配布可能と判断した素材だけを同梱する。記録は利用者の申告である。`.ymmpx` と `ymmpm-transfer.json` は同じフォルダーで保持し、受信側で未使用先に展開する。元素材名・サイズ・SHA-256、同名異内容と異名同内容、出力先競合、登録を承認した場合のIdentityを確認する。失敗・取消後にも元PFと素材が保持されていることを確認する。 [R23手順](v0.5.0-r23-handoff.md)
- [ ] **既存機能**。隔離内でPF整理、一覧保存と復旧、派生Identity、履歴、素材プール、厳格な再リンクを確認する。TLの本番Scene接続は無効を維持する。
- [ ] **判定**。未実行の実GitHub・実YMM4受入をNOT_VERIFIEDとする。実NASと連番PNGの同梱はR24の必須範囲外。対応実証は記載した版・fixtureに限定する。
