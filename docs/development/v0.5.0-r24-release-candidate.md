## 承認済み隔離環境での受入

### GitHubブラウザ認証の操作

1. 対象ホストで、公式GCM 3.0.2 Windows x64が管理者によって保護された機械インストールに置かれていることを確認する。製品は同バージョンの検証済みバイナリをSHA-256で照合する。任意PATH上のGCM、別ビルド、検証機の2.9.1ではブラウザログインを開始しない。製品からGCMをインストール・更新しない。 [GCM公式配布](https://github.com/git-ecosystem/git-credential-manager/releases/tag/v3.0.2)
2. WPFの「GitHubにブラウザでログイン」を選び、表示された認証操作を承認する。既定ブラウザでGitHub.comにログインする。ブラウザに先行ログインしたアカウントがある場合は、意図したアカウントか確認する。未導入・非対応が表示された場合は、起動試行が拒否されたことを記録する。
3. 「認証を中止」で製品の待機を終了できる。ヘルパー起動後は資格情報が更新された可能性がある。再試行する前に「GitHubのアクセスを確認」で対象リポジトリとアカウント状態を確認する。失効・アカウント切替を試す場合は「GitHubにブラウザで再ログイン」を選び、別途承認する。
4. Git操作でWindowsに保存済みの資格情報を使うチェックを有効にし、操作と接続先をそれぞれ承認する。ブラウザ認証成功はリポジトリの権限証明ではない。複数の資格情報が保存され、接続先の応答で一つに絞れない場合は、対話無効のためキャッシュ利用を完了できないことがある。

- [ ] **導入**。試験済みHEADと成果物のSHA-256を記録してから承認済み隔離YMM4へ導入する。再起動後に「ツール」から起動し、製品の版と一連の操作の可否を記録する。
