# v0.5.0 R21 PF 整理・GitHub・Commit・素材プール

**R21 PARTIAL ／ v0.5.0 NOT_READY**。指示 ID `YMMPM-R21-20261121` と両マーカーを確認した。前工程の統合報告と同じ開発スレッドで、基準のローカルツリーがクリーンであり、GitHub とローカルのR20が `2789a5744e79e5941e36fc8eb0691aa125eccbf4` で一致することを確認した。R20 試験済み `23fb52d9b40cf72675f2231420c5f2b0f27431d4` から基準までの相違は Markdown 4件。作業は専用の `codex/ymmpm-v050-r21-pf-cleanup-github-assets` と個別 worktree に分離した。本番YMM4、共有VM、実素材、実GitHub資格情報を使う受入は実施していない。

## 調査と実装

| 機能 | 実装・判断 |
|---|---|
| PF 整理 | PF本体を変更せず、確認した候補と理由を表示して同じフォルダーに別名出力する。固定の YMM4 4.57.0.1 ビルドと現在の `Timelines` 形式で、既定値と一致するルートの `LayoutXml: ""` と `ToolStates: null` のみ対象。非既定値、旧形式、未知のビルドと項目、素材参照、Scene、タイムライン、効果、メタデータを保持。出力は所有ハンドルでハッシュを照合して公開する。 |
| YMMPX | upstream の `RemoveUiSettings`、リフレクションブリッジ、パッケージ読込・展開、参照処理と、隔離した実ライブラリ 1.1.0 を比較。ライブラリの整理オプションは対象2キーを一律に除く。R21 の単体PF整理では、既定値の等価性をDLLのモデル読込で確認した範囲を使用。 |
| GitHub | 公開アクセスは匿名。非公開 Clone、Fetch、二段階 fast-forward Pull、Push、対象リポジトリのアクセス検査には、操作ごとに明示選択した Windows の保存済み GCM 資格情報を使える。GitHub のリテラル HTTPS URL、Program Files の Git/GCM、ロック済み設定を同じ Git で検証。Gitからのヘルパー操作は `get` に限定。HTTP 401 と 403 を区別し、資格情報や子プロセスの生出力を返さない。対話サインインは無効。 |
| Git Commit | 変更一覧、個別ステージ・解除、メッセージ、確定前のステージ済み一覧を WPF に接続。index の候補を検査し、Git の ref ロックの下で親と予定 tree の組を発行。キャンセル、競合、結果不明を分類。必須署名が設定されたリポジトリではアプリから Commit を拒否する。 |
| 素材プール | 収集コマンドで毎回保存先を明示できる。現在の Git commit のPFに元参照があることを確認してから収集。素材とバージョン付き記録を同じ専用ディレクトリに生成。短いSHAは配布名の表示用、照合は完全SHA-256。元ファイル保持、衝突非上書き、任意のURLと利用者の許諾記録を備える。許諾記録は権利判定に使わない。 |
| 厳格再リンク | 明示したフォルダーのみ検索。選択したローカル・メタデータ版の完全SHAと元ファイル名の両方を照合し、複数一致は明示選択する。受信PF内の旧パスは文字列として扱い、宣言された旧PFフォルダーから相対照合できる場合のみ利用する。候補と記録は使用直前に再確認。プロジェクト内は管理付きv5記録で再開でき、外部候補は同じ場所への別名PF出力に対応する。 |
| 素材公開防止 | Stage は入力ファイルを先に検査し、Commit は immutable tree、Push は承認されたOIDから到達できる全コミット・blob・履歴上のパスを検査。既知の素材参照、本文SHAと一般的な改行変換、プール固有パス、パッケージ、バイナリ、LFSポインターを拒否。収集時は保護用の名前とハッシュをリポジトリのGit管理領域に永続化。秘密や素材の実体は記録しない。 |

[PFの仕様と分類](v0.5.0-r21-pf.md) · [GitHubとCommitの設計](v0.5.0-r21-git.md) · [素材プールの仕様](v0.5.0-r21-asset-pool.md)

## 独立レビューと対処

| 優先度 | 確認した事項と処置 |
|---|---|
| P0 | レビュー・試験の範囲に新規の未解決事項なし。 |
| P1 | 旧の別名再リンクで、一時ファイルを閉じた後の合成差し替えが成功扱いで公開されることを独立再現。ハンドルを公開まで保持し、ハッシュを読み戻して修正した。未公開の旧再リンク記録から照合を迂回する経路は拒否し、記録と作業ファイルを保持する。 |
| P1 | 既知素材の記録を永続化し、エスケープされたJSONキーとマージの履歴も検査する。名前がリモート設定と重なる接続先を拒否し、GitHubでは実行に用いる固定Gitで再検査する。GCMの管理ランタイムとシェル起動環境も制限した。 |
| P1 | 同一OIDを示すsymbolic refをGitが置換し得る条件を、Gitが保持するrefロック内で再確認して拒否する。Commit時に進行中マーカーを再確認し、未所有の一時ファイルを削除しない。 |
| P2 | デバイスパスの正規化、記録の必須サイズ、許可先の大文字小文字、送信側絶対パスの相対照合を修正した。ローカルPushの受信側フックは実行され得るため、受信側を管理する場合に限ることを明示する。 |
| P3 | レビューの範囲で新規指摘なし。 |

合成環境でP1の修正を再検証した。Gitの並行操作は通常の index/ref ロックに従う前提。外部プロセスが `.git` を直接編集する場合や、Gitの履歴自体に既に公開済みのデータがある場合の回復は対象外。素材の判断根拠がない通常のテキストを全て素材と識別することはできない。逆に安全側の検査で無関係なバイナリや同名ファイル、上限を超えた履歴を拒否する場合がある。

## 再実行コマンド

Windows の固定ローカル NTFS、.NET SDK 10、Git for Windows を使用する。 `YMM4_PATH` と `YMM4DirPath` はその試験専用の3 DLL参照コピーに限定する。ビルドが配下にプラグイン DLL をコピーするため、実 YMM4 への指定を避ける。 `TEMP` と `TMP` は実行ごとの空の隔離フォルダー。ライブラリありの構成にだけ、隔離コピーの `YMMPX_LIB_PATH` を設定する。

```powershell
dotnet build .\YMMProjectManager.sln -c Release '-p:Version=0.5.0' --nologo
dotnet build .\YMMProjectManager.sln -c Debug '-p:Version=0.5.0' --nologo
dotnet run --project .\YMMProjectManager.Tests -c Release --no-build
dotnet run --project .\YMMProjectManager.Tests -c Debug --no-build
```

重点試験だけを再実行するときは `YMM_TEST_FILTER` に `GitPublicationTests,GitRepositoryTests,AssetPoolTests,ProjectFileCleanupTests,RelinkIntegrityTests,StrictRelinkWorkflowTests,OfflineControlsTests` を指定する。匿名の隔離 HTTPS は `GitHttpsAcceptanceTests` を指定する。全回帰の際は `YMM_TEST_FILTER` を解除する。

最初の4構成は旧WPF試験の前提が原因で、各1グループが失敗した。項目名を単一のステータス文字列に求めていた試験を、新しい変更一覧の表示・選択・プロジェクト切替を確認するものに更新した。テストをスキップせず、修正後の統合HEADで全構成を再実行した。

試験済みHEADは `c4d9e8e5488e2f5f2a924c8029133936c181708c`。Release・Debugビルドはともに終了0、警告0、エラー0。最終テストは全行で終了0。

## 未検証と再開条件

1. **隔離済み実YMM4**。PF読み込み、WPFのステージ・Git操作・再リンク、既存データの更新と復旧を、別途承認された合成プロファイルで確認する。非既定の UI 状態、別のYMM4ビルド、TL の実 Scene 接続・実験用Pbgra32、アクティブタイムラインの書き換えは無効のまま。
2. **実GitHub認証**。許可済みの公開・非公開テスト専用リポジトリで、匿名、明示選択したGCM、資格情報なし、取消、権限違い、Clone/Fetch/Pull/Pushを確認する。公開リポジトリのアクセス成功だけではログイン済みか判断できず、非公開の404では存在と権限を区別できない。GitHub Enterprise、対話サインイン、複数アカウント・SSOの実受入は未実施。
3. **実NAS／UNC**。専用共有で収集、非上書きディレクトリ公開、意図的な切断・再試行、受信側の明示選択を確認する。合成試験では切断相当例外を使った。実共有でのファイル所有・共有・renameの互換性は未検証。
4. **外部候補の関連付け**。別名PFは作成できる。外部素材の配置と版を再検証して引き継ぐ契約が未確立のため、出力へのメタデータ自動移行は行わない。元の履歴と登録を保ったまま、場所を再承認できる記録を設計してから検証する。
5. **電源断**。Flush、原子的なファイル公開、合成の中断からの再試行を検証した。障害による永続性は別途検証が必要。
