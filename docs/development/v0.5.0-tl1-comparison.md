# v0.5.0 TL-1 プレビューフレーム比較

TL-1 は、2つの Scene スナップショットに属するプレビューフレームの時刻合わせと、供給済みの画素バッファの比較を提供する。実行経路は `Application/PreviewComparison` 内で完結する。PM の既存プレビュー取得とシークは、WPF およびアクティブタイムラインに依存する既存経路として扱う。比較処理への呼び出しは、現時点では合成テストから行う。

## 時刻合わせ

`PreviewComparisonRequest` に、共通の開始点からの非負の `TimeSpan` と A/B のソース記述を渡す。ソースはスナップショット ID、描画設定 ID、正の有理数 FPS、0 以上のフレーム数を持つ。描画設定 ID は両者で共通とし、フレームレートは個別に宣言する。別スナップショットを指定する。

フレームは0始まり。ソースごとに `floor(timestampTicks × fpsNumerator / (10,000,000 × fpsDenominator))` を整数演算で求める。整数積には `Int128` を使う。各フレームは開始を含み、終端を含まない区間を表す。正確な境界が `TimeSpan` の100 ns単位で表現できない場合、最初に新しいフレームを選ぶ時刻は境界以上の最小 tick となる。30 fps のフレーム1は tick 333,334 から選ばれる。

- 同じ FPS では同じ時刻が同じインデックスを指す。フレーム数が異なる場合、比較可能なのは短い方の尺の終端より前まで。
- 異なる FPS では同じ時刻を各ソースに写し、各ソースでその時刻を含むフレームを選ぶ。開始位置は両者で同じ論理原点を使う。尺の比率による伸縮や位置補正は扱わない。
- ソースの終端は厳密に `frameCount / fps` 秒で、その時刻から範囲外。空の Scene も範囲外になる。片側だけ範囲に入る場合は有効側の位置と範囲外の側を返し、比較全体を不成立にする。
- `PreviewFrameAlignment.Align` を描画前の検査に使える。比較時にも同じ規則を適用し、供給フレームのソース記述とインデックスを要求と照合する。成功結果のフレーム位置は両者の一致確認後の値。

## 画素の契約

各画像は上から下の行順に詰めた **straight BGRA32** の `ReadOnlyMemory<byte>`。各画素は B・G・R・A の順に1バイトずつ並ぶ。パディングなし、正の幅と高さ、バッファ長が厳密に幅 × 高さ × 4。両画像は幅、高さ、形式が一致する必要がある。0 や負の寸法、長さを `int` で表せない寸法、過不足のあるデータ、形式不一致、同じ未対応形式を個別に扱う。

メトリクスは対象の寸法、4チャンネル完全一致、1チャンネル以上異なる画素数と百分率、全チャンネル差の絶対値合計、MAE（合計 ÷ 全チャンネル数）、最大チャンネル差。alpha も1チャンネルとして数える。alpha が 0 の画素でも格納されている RGB を比較する。Pbgra32 などとの混在を拒否し、色変換・リサイズ・背景合成は行わない。

1回の走査で計算し、入力以外の追加領域は一定。差の合計には `long` を使う。差分画像の生成・自動保存は TL-1 の対象外。呼び出し元が比較完了まで元バッファを保持し、変更・再利用を避ける。同時比較では、各呼び出しが独立したバッファまたは変更されない共有バッファを使う。

要求の問題、フレーム情報の不一致、画像契約の違反は分類値を返す。片側に特定できる場合は A/B を付ける。取り消しは開始時と走査中の4,096画素ごと、走査終了時に確認し、標準の `OperationCanceledException` で通知する。結果にバッファやファイルパスを保持しない。
