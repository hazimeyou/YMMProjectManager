## 実装の確認箇所

- **保存と再開** `JsonProjectRepository`、`ProjectListDrafts`、`ProjectListPublications`。取得前にチェックサム付きのレシートを公開し、下書きと操作 ID を同時に確認する。操作 ID と SHA-256 を明示的に検証して以前の公開結果まで遡る。競合・証拠欠落では回復資料を保持する。別プロセスの中断テストあり。
- **旧形式と三者マージ** `ProjectListMerge`、`ProjectListIdentityRecovery`、`ProjectListConflictReview`。競合時の保存先・識別情報・関連付け・リンクを組として扱い、取り違えを防ぐ。保存前に採用したファイルを開いて、書き込みが終わるまで保持する。未知フィールドはルートと安定 ID 付きの行で保持し、保持できない場合は別名退避する。重複・未設定 ID は明示確認の上で原本を退避して反映する。
- **メタデータと再リンク** `AssetRevisionSeries`、`AssetRelinkRecovery`。分岐した旧履歴は原本を残して同じバイト列を取り込む。分岐の先端集合をレシートに記録し、指定した先端への追加のみを許可する。候補と出力を照合し、再試行で同じ版を二重作成しない。選択版を保持した履歴ディレクトリの再設定と、外部保管先の明示照合を利用できる。
- **Git** `GitRepository`、`GitRepositoryLease`、`ProjectListGitAssessment`。Pull の状態確認ではローカルの追跡 ref を読む。Fetch・Push では承認した物理リポジトリを再照合する。実際に書き込む Pull は停止中。承認対象と状態が変わった場合は実行を拒否する。
- **YMMPX** `YmmpxLibInstallGuide`、`YmmpxPackageReader`、`YmmpxLibBridge`。完成したダウンロードのみを公開する。展開失敗時は所有を確認したファイルのみを後始末し、残存先を報告する。WPF からインストーラーのダウンロードを中止できる。既存の出力と素材は保持する。

## ビルド・試験コマンド

隔離した Windows 作業環境を使用する。YMM4 の参照 DLL 一式を専用ディレクトリへコピーし、`YMM4_PATH` と `YMM4DirPath` に指定する。`TEMP` と `TMP` は合成データ用の独立した領域に設定する。実ライブラリありの試験では `YMMPX_LIB_PATH` を隔離済み `YmmpxLib.dll` に設定する。書き込み先・Git 設定は試験領域内に限定する。

```powershell
dotnet build .\YMMProjectManager.sln -c Release "-p:YMM4_PATH=$env:YMM4_PATH" --nologo
dotnet build .\YMMProjectManager.sln -c Debug "-p:YMM4_PATH=$env:YMM4_PATH" --nologo
dotnet run --project .\YMMProjectManager.Tests -c Release --no-build
dotnet run --project .\YMMProjectManager.Tests -c Debug --no-build
$env:YMM_TEST_FILTER = 'RealYmmpxR5'
dotnet run --project .\YMMProjectManager.Tests -c Release --no-build
```

再実行時は `YMM_TEST_FILTER` を解除してから全回帰を開始する。停止中の Pull、実 DLL なし構成のライブラリ検証は明示スキップ。個別計測はグループ内の一部であり、個別とグループ件数を合算しない。中断試験は実子プロセスのルート内で行う。OS や電源の停止試験は含まない。

Git remote・一覧公開・一覧回復を同一 HEAD で3回連続再実行した。各回は終了コード0、個別計測20件成功、明示スキップ1件。24時間等の長時間安定性は未評価。途中の再試行では初回 push が `PathTooLong` を返した。テストの失敗表示に分類と終了コードを追加し、短い隔離先を使用した。これは過去の divergence 分類の再発ではない。

途中では共有一時ディレクトリが YMMPX とサムネイルの試験出力を混在させた。インストーラーテストをケース専用の一時先に変更し、全回帰の環境も分離した。世代 Manifest では `File.OpenRead` の共有設定が、同じ試験内の並行保存の原子的置換を拒否した。読み取りハンドルに削除共有を許可した。隔離した Windows ファイル試験で旧設定の拒否、新設定で旧ハンドルと新ハンドルがそれぞれ旧版と新版を読むことを確認した。非協調ライターがハッシュ確認の直後に差し替える余地は残る。

## 独立レビュー

- 一覧の復元で未知フィールドを落とす条件と、複数パスが同じ物理ファイルを指す条件を指摘された。前者は保持できない保存を拒否し、後者は競合として止める実装と回帰を追加した。
- 再リンク候補を二度ハッシュする箇所を修正し、選択時の照合と保存直前の候補の同一性確認を維持した。Git Clone の物理ディレクトリ予約・公開と最終のインストーラー／世代 Manifest 差分の独立レビューでは、高重大度の問題は確認されなかった。独立レビューの試験実行は行っていない。
- 残る指摘は、再保存で新旧の ready 記録が同時に残る場合の世代管理。閉じた記録は明示的に別ファイルへ退避できる。証拠が不足している状態では自動再適用せず、診断と手動選択を維持する。
