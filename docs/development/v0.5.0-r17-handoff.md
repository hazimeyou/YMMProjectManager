## 挙動と回復の確認

- **一覧保存**。元版と候補の物理 ID・SHA-256 を照合し、退避後に現用名が空いている場合だけ候補を公開する。外部版が入ったときは保全し、古い下書きを自動で再適用しない。「中断された一覧保存を確認」から現用・退避・候補を区別し、検証済み元版または外部版を明示確認して、空いている現用名へ戻す。既存の現用版を上書きしない。互換性のある固定ローカル NTFS の通常ファイルを対象とし、現用名が一時的に存在しないことは他のアプリから観測できる。電源断の耐久性や監査 SACL は未確認。 [一覧 ADR](../architecture/adr/project-list-publication-r17.md)
- **Git**。書き込みを伴う Pull は無効。アプリ内協調と Git の管理ロックのほか、実 HEAD ファイルハンドルで保持しても index と作業ファイルが先に変わる場合を確認した。読み取り診断に無視対象との衝突を表示し、日本語のパスと履歴を UTF-8 で取り扱う。 [Pull ADR](../architecture/adr/git-pull-recovery-r17.md)
- **管理付き再リンクと履歴移行**。初回と回復の双方で、書き手ロック下でメタデータの枝を照合してから出力を公開する。元や候補の欠落、枝の更新、保存先の競合では記録を保持する。メタデータ移行は確認済みの作業フォルダーを上書きなしで公開し、作業内容が曖昧ならフォルダーを保持。フラッシュ済みの出力と版の確定の間には再開できる区間が残る。 [R16 契約と互換性](../architecture/adr/managed-relink-publication-r16.md)
- **YMMPX と関連ワークフロー**。現行形式の作業ディレクトリを固定し、選択したプロジェクト名と検証済みアーカイブを照合。所有不明の一時ファイルは保持する。同じ権限のプロセスが作業ディレクトリ内に同名かつ有効な別内容を置ける条件では元データとの同一性を証明できない。メタデータ移行も公開直前の外部による作業ファイル内容変更は対象外。外部素材の一括照合を UI スレッド外に移し、世代の復旧が失敗したときは両方の保存場所を通知する。

## 検証方法

隔離コピーした YMM4 の参照 DLL を `YMM4_PATH` に指定。並行起動時は短い専用フォルダーをプロセスごとに設定し、`TEMP` と `TMP` を分ける。実 YmmpxLib ありの回だけ `YMMPX_LIB_PATH` を信頼できる隔離 DLL に設定する。Git はローカルの一時リポジトリと bare remote を使用した。

```powershell
dotnet build .\YMMProjectManager.sln -c Release "-p:YMM4_PATH=$env:YMM4_PATH" --nologo
dotnet build .\YMMProjectManager.sln -c Debug "-p:YMM4_PATH=$env:YMM4_PATH" --nologo
dotnet run --project .\YMMProjectManager.Tests -c Release --no-build
dotnet run --project .\YMMProjectManager.Tests -c Debug --no-build
$env:YMM_TEST_FILTER = 'ProjectListPublicationTests,ProjectListIdentityRecoveryTests,AssetManifestTests,YmmpxFailureTests,RealYmmpxR5,OfflineControlsTests'
dotnet run --project .\YMMProjectManager.Tests -c Release --no-build
$env:YMM_TEST_FILTER = 'GitRemoteTests'
dotnet run --project .\YMMProjectManager.Tests -c Debug --no-build
```

## 残件と停止判断

- **R17-A / P0**。既存 checkout に対する Git Pull を有効化するには、外部 Git と編集ツールを含む排他が必要。その上で、対象 ref・index・作業ツリーの各公開点でプロセスを中断し、復旧後に整合することを検証する。通常の Git クライアントと共用する現行構成では排他を実証できなかった。次は `GitRepository.PullAsync` と隔離 `GitRemoteTests` を起点に、書き込み主体を特定できる checkout の設計を試す。別の場所への安全なコピーを既存 checkout の Pull とみなすには製品判断が必要。
- **R17-B の条件外**。固定ローカル NTFS の対応する通常ファイルで試験済み。追加属性や権限を保持できない構成は書き込みを拒否する。残る受入は、実ファイルシステム・監査設定・電源断を扱える専用環境と互換性判断を要する。中断・外部競合の合成試験と WPF ガイダンスは今ラウンドで追加した。
- **R17-D の作業ディレクトリ内部への介入**。所有を証明できない一時ファイルの削除を止めた。信頼済み実 DLL の現行形式を維持しており、同じ権限の別プロセスに作業ファイルの書き込みを許さない動作環境、または選択した元プロジェクトと生成物をより強く結び付けるライブラリ契約が次の条件。Unicode と無関連フィールドを保持する実 DLL の合成試験を追加した。
- **R17-E**。旧 YMMPX の実資料は Git 管理ファイルと履歴に見つからなかった。実ホスト・実認証も隔離した受入環境の提供待ち。現行形式とローカル Git の試験は独立して実施した。
- **R17-F**。アクティブタイムラインは **STRETCH_GOAL / DISABLED**。YMMPrint の別タスクの確定結果はこの作業で利用できず、調査の重複・独自タイムライン・レンダラーの実装は行わない。実環境で契約を検証できる段階で接続条件を整理する。

Git Pull の未解決だけを理由に停止せず、一覧、Identity・再リンク、YMMPX、外部素材、世代診断、WPF、独立レビューと最終回帰を進めた。残作業は排他契約、互換性の決定、アクセス境界または未提供の実 fixture に依存する。11月25日のレビューには現コードと検証資料を引き渡せる。

統合ツリーと各 worker の枝・worktree を保持した。main/master、既存 PR、実プロジェクト、YMM4、YMMPrint、共有 VM は変更していない。
