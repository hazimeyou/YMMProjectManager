# R33 YMMPXの公開境界

## 除外設定の競合対策

R32では作成前の確認で見つからない設定を空として扱い、公開直前にもう一度不在を確認していた。確認後に設定が作成されると、古い除外状態のままパッケージを公開できた。既存設定は、以前から公開まで物理IDとSHA-256を照合した読み取りハンドルで保持している。

再確認だけでは直後の作成を防げない。PM独自のロック名は協力する取込処理としか調停できない。本番設定を恒久的に初期化する方法には、作成した設定が後続の取込へ影響する問題がある。

不在だった設定は、パッケージ検証後の短い公開区間に限り、正規のファイル名を共有なしの新規作成で予約する。Windowsの `CREATE_NEW`、`FILE_FLAG_OPEN_REPARSE_POINT`、`FILE_FLAG_DELETE_ON_CLOSE` を使う。競合が先に正規名を取得した場合は公開を取りやめる。予約後は、同じ名前への通常の作成・更新・移動が拒否される。以前の設定が退避されたままの事例を逃さないよう、予約後に `.previous-*` も照合する。複数設定のうち1つでも保護できなければ、すでに取得した予約を解放する。

成功・取消・公開失敗時にはハンドルを閉じ、予約を解放する。Windows 11のローカルファイル上で、専用試験プロセスの強制終了時にも解放されることを合成fixtureで確認した。予約中に取込や参照が競合した場合は安全停止し、解放後に再試行できる。停電やファイルシステム障害を含む複数ディレクトリ間のトランザクションは受入対象外である。

## 互換性

[参照Packager](https://github.com/hazimeyou/YMMResourcePackager/tree/2a767c8b4922cb0aa1f0cf6fdaf8a3ea6a0bc53a) のコミットはR32時点と一致した。公式YmmpxLib 1.1.0と同じ合成PFを使う既存の直接比較により、代表画像が欠落または除外された連番PNGの同梱バイトを照合した。PMの読取りルート制限や、各連番素材への除外適用は維持した。標準YMMPX、PM v1と開発時v2、旧ライブラリ公開版で生成された合成アーカイブの読み取りは、従来の経路で動作する。重複エントリーの明示的な拒否試験を追加した。

実ホストやVMの受入はこの検証には含めていない。
