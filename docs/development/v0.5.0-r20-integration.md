## ネイティブ Git 更新途中の中断

専用 bare remote と固定ローカル NTFS 上の checkout を使用した。最初の試行は Git を強制終了した時点ですでに HEAD、index、作業ファイルが更新済みだったため、途中の証拠から除外した。

改良した試験では、合成的な外部読み手がローカル ref を読み取り共有で保持した。テストは、承認済みの `git merge` 子プロセスの実体を取得し、内容の SHA-256 が一致するファイルが現れ、同じ子プロセスが稼働中であることを確認してから、その子プロセスだけを停止した。Windows の強制終了コード `-1` を条件にし、自然な共有違反による終了を成功条件に含めない。

| 観測項目 | 結果 |
|---|---|
| HEAD と branch | 承認前のローカル commit と branch のまま。承認した新 commit に到達しなかった。 |
| index と作業ファイル | 変更が反映された。index が対象 tree に合う実行を観測した。実行ごとの index SHA-256、lock、反映ファイル数はログで記録。 |
| 元ファイル | 元の合成プロジェクトと事前に存在した ignored ファイルの SHA-256 を保持。更新中に別処理として加えた非衝突の untracked ファイルも保持。 |
| 操作結果 | `OutcomeUnknown`。旧・新 OID と操作 ID を持つ回復記録を保持。 |
| 再起動相当 | 新規プロセスの2回の照会と別インスタンスの再試行がともに拒否。HEAD、index、作業状態、lock、記録の保持を確認。自動復旧なし。 |

実測した地点は、作業ファイルの更新開始後で、承認済み ref に到達する前。停止時の別ディスク状態や Git 内部の実装順序、全ての更新境界、電源断の回復性は未検証。戻し先と状態が確定するまで元ファイルと操作記録を保全し、復旧は利用者の明示判断に委ねる。

## 試験環境

Windows の固定ローカル NTFS、Git for Windows、.NET 10 を使用。YMM4 参照 DLL は隔離コピーし、ビルド時に `YMM4_PATH` と `YMM4DirPath` を同じ専用参照ディレクトリに渡した。 `CopyToYMM4` が書き込む場合もその配下だけに限定した。テストは個別の短い `TEMP` と `TMP` を使い、実 YmmpxLib ありの構成だけに隔離 DLL を指定した。

```powershell
dotnet build .\YMMProjectManager.sln -c Release "-p:YMM4_PATH=$env:YMM4_PATH" "-p:YMM4DirPath=$env:YMM4_PATH" --nologo
dotnet build .\YMMProjectManager.sln -c Debug "-p:YMM4_PATH=$env:YMM4_PATH" "-p:YMM4DirPath=$env:YMM4_PATH" --nologo
dotnet run --project .\YMMProjectManager.Tests -c Release --no-build
dotnet run --project .\YMMProjectManager.Tests -c Debug --no-build
```
