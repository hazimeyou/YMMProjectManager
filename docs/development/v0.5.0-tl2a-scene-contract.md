# v0.5.0 TL-2A Scene 比較受け渡し契約

**ホスト接続は無効。** ここで定義するのは PM 側の値と検査であり、SDK による保証やアダプターの実装は含まない。PM の `TimelineContextService` はツール提供の `TimelineToolInfo` を保持する。既存の seek アダプターは CurrentFrame や編集コマンドに作用し、既存の BitmapCapture アダプターは現プレビューの探索を行う。これらは今回の Scene リゾルバーや寿命の証明に使用していない。ディスク上の AssetManifest のリビジョンは、未保存のホスト編集を観測できない。

## 根拠

YMMPrint の R1 `ef6a93b8099b92afe7172012abb0ea6c35daecd2` と R2 `5140548669b5d136802d967875ca18c2da6333ce` を読み取り調査した。`docs/research/tl-preview-api-map.md`、`tl-preview-r2-acceptance.md`、`tl-preview-r2-pm-handoff.md`、`research/TlPreview/Probe/NativeSceneTarget.cs` が参照元。R2 は5版で20ビルド、77の合成アサーションを報告している。公開型とコンパイルでは `Scene.TryCreateVideoSource` → `Update` → `RenderBitmapSource` を確認。静的 IL には GPU リソースの生成・解放経路と ViewModel の共有設定参照が見える。実 Scene、実行時リソースの独立性、ホスト全体の排他、実画素契約は未受入で、R2 の製品接続判定は HOLD。

## 発行、描画、応答

1. 将来のホスト境界は、権威ある所有者から同じセッション・プロジェクト・リビジョン内の別 Scene を読取りで解決する。`SceneSnapshot` はホストセッション、プロジェクト、リビジョン、Scene、Scene オブジェクトの寿命、既存 `PreviewSource` を結び付ける。ID はパスや生の SDK 参照を持たない不透明な値。Scene GUID の一致に加えて実オブジェクトと owner membership を確認する。寿命トークンはセッション内で実体ごとに発行し、再読込・置換・離脱・終了後に再使用しない。編集でリビジョンを更新し、元の内容に戻ってもトークンを戻さない。信頼できる観測を得られないときは処理を始めない。
2. `SceneComparisonPlan.Prepare` は一致すべき束縛、別 Scene、描画設定、出力寸法、フレーム範囲を検査し、A/B 別の操作 ID を発行する。要求は共通の正確な `TimeSpan`、各 Scene の0始まりフレーム、FPS、フレーム数を含む。尺はフレーム数 ÷ FPS。TL-1 の時刻切り下げと半開区間を使い、範囲外は側別情報を返して操作を発行しない。ホストは選択されたフレームを SDK の適切な時刻へ変換し、実際のフレームを確認する。要求 tick の丸め直しや要求フレーム値の単純な復唱で受領確認を代用しない。
3. 描画設定 ID は寸法、背景、画質、色空間と伝達特性、alpha、効果とアニメーションの条件を表す共通の契約に対して発行する。FPS は別途ソースが持つ。設定条件や出力形式が不明なら中止する。A/B の操作 ID は各描画試行に相関させ、再取得や再試行には新しい操作 ID を発行する。TL-2B の A 再描画にも別の識別子を使う。TL-2A の計画は A/B の合成用で、再描画のオーケストレーションは持たない。
4. 検証済み UI Dispatcher とホスト全体の非再入条件下で、owner とリビジョンをキュー実行時、各描画の前、画素のコピー後に再確認する。描画はまず A→B→A の逐次試験。ホスト所有の Scene、Timeline、UndoRedoManager、AsyncAwaitStatus は借用し、アダプターから Dispose しない。返却された source はスコープ内で一度解放し、source.Devices を別に解放しない。同期 SDK 呼び出しは強制中断せず、境界で取消を観測する。描画と解放の同時故障は両方記録する。
5. `SceneRenderResponse` は操作 ID、観測済み束縛、実フレーム、寸法、stride、画素形式、借用画素を返す。Copy は計画の A/B スロットから要求を引き、相関と出力条件を検査して所有コピーを作る。所有コピーは借用ストレージの変更・再利用・解放から独立する。`Compare` は計画の所有コピーと最新の A/B 観測を照合する。結果の外部公開直前にも、観測と公開を一貫したホスト境界内で行う。値の等値比較だけで観測の鮮度や実フレームを証明することはできない。
6. 束縛、相関、フレーム、出力の契約違反は分類し、該当側を付けられる箇所では付ける。取消は `OperationCanceledException`。失効、ホスト拒否、SDK 故障、状態観測不能及び解放故障は、将来のアダプターが別の結果として扱う。結果・通常の診断にパスや生フレームを含めない。

## 画素、stride と変換

R2 Probe が受けるのは WPF `BitmapSource`。元の Format と PixelWidth/Height を参照し、必要なら `FormatConvertedBitmap` を使い、幅×4を出力 stride として独立コピーする。実 Scene の元形式・元 stride、色空間や伝達特性、DPI は未確定。DPI は今回の画素寸法・画素メトリクスに使用しない。将来、異なる DPI がレンダリングの寸法やスケーリングに影響する場合は描画設定に含める。

TL-2A が受けるのは **宣言済み straight BGRA32 の top-down 行**。正の stride は幅×4以上。末尾行のパディングを含む stride×高さとバッファ長が一致する。packed 出力でも独立コピーを保持し、余分な行バイトを除く。借用、所有の各バッファの上限は 32 MiB。入力を変更せず、1回のコピーは最大64 KiBごとに取消を確認する。色や alpha は各バイトをそのままコピーする。alpha 0の RGB も保持する。

Pbgra32、未宣言の形式、反転行は拒否する。R2 の合成 WPF 例では Pbgra32 の `(0,0,64,128)` が straight の `(0,0,127,128)` となった。逆乗算で失った情報や alpha 0 の元 RGB は復元できない。実形式・色空間・透明画素の扱いを確定し、丸め・clamp・alpha 0方針を試験するまで本番変換は保留。

## 状態保全と観測

分類は R2 が示す公開型・観測の候補に対する評価。実行前後の一致は現時点で未確認。失敗・取消・解放時にも観測し、変更を検出した場合は結果を破棄する。編集の競合を上書きしうる自動復元は行わない。

| 状態 | 観測区分 | 根拠と不足 |
| --- | --- | --- |
| CurrentFrame | VERIFIABLE | 既知の借用 Timeline の公開 getter。実測で前後および評価中を確認する。 |
| アクティブ Scene、可視シーク | PARTIALLY_OBSERVABLE | R2 の可視 Timeline/seek 観測器は caller 注入。対象外のビューにも効く正式な所有者解決は未確立。 |
| 選択アイテム・レイヤー | PARTIALLY_OBSERVABLE | 選択 getter の公開型を確認。各ビューと対応する実行時の観測は未検証。 |
| Undo/Redo | PARTIALLY_OBSERVABLE | 可否と履歴イベントの型は確認可。履歴内容・カーソルの不変は可否だけで立証できない。 |
| 既存プレビュー | PARTIALLY_OBSERVABLE | 再生状態の getter 候補あり。画素、非表示資源、内部キャッシュの全体比較は未確立。 |
| アクティブプロジェクト | UNOBSERVABLE | 実行中の owner、世代、終了を安全に結ぶ正式契約が未確立。 |
| dirty、編集コマンド | UNOBSERVABLE | dirty の全体スナップショットと、コマンドの実行・副作用がなかったことの観測契約が未確立。 |

状態を網羅できる観測と非再入契約を確立するまで、製品経路を無効のまま維持する。画素の一致は対象フレームの比較結果であり、素材・参照先・プロジェクト構造の同一性の検証は別に必要。
