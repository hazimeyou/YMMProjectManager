# R22 外部素材再リンクの派生プロジェクトと回復

外部素材を使う別名保存では、元の登録先とその履歴を保持し、新しいPFを独立したプロジェクトとして登録する。既存の同一ID移行方式では、元PFの一覧登録が出力に切り替わる。元の登録と新しい登録を両方残す操作には、それぞれ異なるIDを割り当て、元のルート・選択版・PFのSHA-256を派生履歴のルートに記録する。元の履歴は書き換えない。

## 証拠と公開

1. `.ymmpm-relink-external-<操作ID>.json` に元PFの物理IDとSHA-256、元履歴のルート・選択先端、出力パスと予想SHA-256、派生ID・ルートSHA-256、許可ルート、元素材名・完全SHA-256と任意の素材manifestのSHA-256を記録する。
2. 元PFと素材を検証してから、R21と同じ所有ハンドルで別名の作業ファイルを作る。公開証拠に出力の物理ファイルIDを記録した後に限り、未公開の作業ファイルを回復に使える。
3. 元履歴の選択版と全先端、作業ファイルの物理IDとSHA-256、明示許可ルート内の素材とmanifestを再検証する。派生ルートを同一フォルダーの `.ymmpm-derived-<派生ID>` に非上書きで公開し、既に同じものがある場合は一致を確認する。出力PFは同じフォルダーへの所有ハンドルによる非上書きrenameで公開する。
4. 公開済みファイルを読み取りハンドルで開き直し、物理IDとSHA-256を照合する。両PF、両履歴の版ファイル、素材とmanifestの読み取り保持を続け、一覧の登録に渡す。

派生メタデータは元素材名、完全SHA-256、許可ルートからの相対パス、出力PFの外部参照を照合するためのパスのSHA-256を持つ。元のパスは文字列として扱う。回復用の許可ルートはローカル証拠に記録し、再試行時は同じ場所を明示承認する。相対名とSHA-256の照合だけで未承認領域にアクセスすることはない。素材のコピー・ダウンロードは行わない。旧manifestに新しい任意フィールドがない場合、シリアライズ出力と旧版SHA-256の契約は維持される。

## 中断時

| 状態 | 処理 |
|---|---|
| 作業ファイル・公開証拠・出力・派生履歴がすべて存在しない | 未ステージと表示。記録を保持し、利用者が新しい操作としてやり直す。 |
| 公開証拠と作業ファイル、または公開証拠と出力が存在 | 許可ルートを再承認したうえで照合する。確定済みの派生IDと出力を再利用する。 |
| 双方の出力が存在、証拠欠落、物理IDの不一致、読み取り不能など | 不明として停止。既存ファイル・履歴・証拠を保持する。 |
| 出力済みで一覧の登録に失敗 | 同じ操作を選び、確定済みの派生IDで登録を再試行する。 |

データファイルと一覧への書き込みを1回のファイルシステム操作にまとめる案では、既存のプロジェクト一覧・履歴の保存契約を置き換える必要がある。R22は既存契約を再利用し、部分成功を明示する。旧R21までの回復記録は既存の読込経路を使う。並行操作に対して共有モードと既存の履歴ロックを使う。電源断と実NASの共有モード・物理IDの挙動は別途受入が必要。
