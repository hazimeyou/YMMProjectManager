# ADR — 一覧保存の公開結果を識別する

一覧 JSON の置換と下書きの整理は別のファイル操作である。従来は置換の直後に停止すると、下書きの名前から保存されたかどうかを判定できなかった。

## 決定

実際に公開する JSON に、保存ごとに一意の `SaveOperationId` を入れる。置換前に、操作 ID、期待する基準 SHA-256、公開する JSON の SHA-256、関連する下書き ID を含むレシートを、チェックサム付きの新規ファイルとして保存する。レシートと一時ファイルはフラッシュする。一覧の排他ロック下で現在のファイルを照合し、同じディレクトリの一時ファイルから置換する。

- 現在の一覧の操作 ID と SHA-256 が一致すれば、その保存を確定し、下書きを閉じる。
- 現在の一覧が期待した基準と同じで、レシートが公開開始前を示すか、置換が消費するはずの操作固有の一時ファイルが残れば、下書きを確認・再適用できる状態に戻す。公開開始の状態は置換前にレシートへ原子的に記録する。再適用前に最新の一覧とマージして、保存時にも照合する。
- レシートの記録前に停止した場合、証拠の破損・欠落、より新しい一覧への入れ替え後など、成否の証明が揃わない場合は記録を保持する。検証済みの下書きは別名退避できる。

通常保存と照合は同じ協調ロックを使用する。保存は下書きの読み取りハンドルも保持し、処理中の下書き名の移動を拒否する。原本と履歴の自動削除は行わず、孤立した一時ファイルとレシートは診断に残す。

## 互換性と切り戻し

操作 ID のない旧一覧は引き続き読み込む。明示的に保存した時点で新しい操作 ID が入る。旧バージョンへの切り戻し前には一覧・回復フォルダーを別途退避する。新規ファイルへの復旧エクスポートには操作 ID を含めない。新しいファイル識別情報等を含む JSON は、旧版が書き込みを拒否する場合がある。

プロセス終了試験はフラッシュと原子的置換の順序を検証する。電源断、ストレージ故障、協調ロックを使わない同一ユーザープロセスからのファイル差し替え、任意のバックアップ復元履歴の全追跡は対象外。
