# R32 旧世代PFの救済

D06で世代の作成・一覧・削除・上書き復元を終了する。Git履歴へ手動で登録する際は通常のStage・Commit・Push前検査が適用される。既存の世代ファイル・目録・復元前バックアップは移動・削除しない。

## 操作

1. プロジェクトマネージャーで「旧世代からPFを取り出す」を開く。一覧に元PFの登録がなくても操作できる。
2. 保存済み世代は `%AppData%/YMMProjectManager/Generations/projects/<旧プロジェクトID>/generations/<世代ID>/metadata.json`、退避済み世代は同じプロジェクトID下の `deleted/<世代ID>_<時刻>/metadata.json` を選ぶ。コピーした世代を使う場合も `generations` または `deleted` の配下に世代フォルダーとその中の2ファイルを維持する。
3. 選択した世代を確認し、新しい `.ymmp` のパスを指定する。元PFと異なるフォルダーに出力すると相対素材参照の解決先が変わる場合がある。素材本体は世代に含まれない。

救済は、選択された `metadata.json` と同じフォルダーの `project.ymmp` に限定する。目録からパスを解決する方式では、破損目録や元PFの移動で有効なスナップショットに到達できなくなるため、世代単体を選ぶ方式を採用した。破損目録はそのまま保全する。当時のメタデータとサイズ・完全SHA-256を照合し、確認後に物理ファイルが変わった場合は中止する。照合結果が示すのは、取得したデータと選択したメタデータの整合性である。

元PF、旧保管先、既存ファイルへの公開は拒否する。出力ディレクトリに作成した一時ファイルを検証した後に非上書きで公開する。取消・競合時は操作が所有する一時ファイルのみ片付ける。回復証拠が壊れている場合は自動修復せず、欠損ファイルと残存ファイルを保全する。`restore-backups` 内の `*_before-restore.ymmp` は既に独立したPFなので、利用する場合は新しい場所にコピーして確認する。

現行コードは旧世代を更新しないため、元の保存・復元方式に戻す目的でデータ変換を行う必要はない。旧版を起動する前に元PFと世代ディレクトリを別途保全する。
