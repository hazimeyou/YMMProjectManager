# ADR: R17 プロジェクト一覧の外部置換と回復

状態 **採用（ローカルの固定 NTFS、対応する通常ファイル）**。単一の原子的な比較交換を提供する方式ではない。

## 変更理由

R16 は読み取りハンドルを SHA-256 照合から `File.Replace` まで維持した。削除共有によって直接書き込みは拒否したが、別プロセスが同じ名前へファイルを入れ替えたときに、その新しい版を確認せず上書きし得た。置換時にバックアップ先を渡すだけでは外部版が現用パスから押し出される。

## 保存契約

1. 製品間の保存を既存のプロセス間ロックで直列化し、親ディレクトリを上書きのない操作の間保持する。
2. 無共有の作業ファイルと読み取りリースを使い、元ファイルと作業ファイルの所有者・グループ・DACL、通常属性、拡張アクセス方針、名前付きストリームを確認する。安全に再現できないファイルには一覧の内容を書き始めない。作業ファイルの内容をフラッシュし、検証する。
3. 現用の SHA-256 と物理ファイル ID を取得する。既存一覧のある場合、元と候補の証拠を収めたチェックサム付き操作記録を同じ親内へフラッシュして公開する。
4. 現用名で実際に取得されたファイルを、操作固有の空き退避名へ移動する。退避ファイルのハンドルを開き、元版の物理 ID・SHA-256 とファイル属性を確認する。違えば候補を公開しない。元版の場合だけ、作成時刻を確認済み候補へ引き継ぎ、候補のハンドルから現用名へ上書きなしで公開する。
5. 退避後に外部プロセスが現用名を作成すれば、そのファイルを維持し、退避ファイル・候補・操作記録も保持する。成功後は検証された旧版と完了済みの操作記録だけを後始末する。中断や確認不能時は記録を保持する。

初めての保存は空きパスへの公開だけを使う。既存一覧のバイト列と同名の外部版でも、退避した物理ファイル ID が違えば候補を公開しない。下書きの旧形式とレシート形式はそのまま読み取れる。

## 明示的な回復

| 観測した状態 | 回復動作 |
| --- | --- |
| 現用名に元版が残る、または候補公開が確定 | 選択時と同一の現用版を保持し、操作記録を閉じる。 |
| 現用名が空いていて、元版の退避を確認 | 再照合した元版ハンドルだけを現用名へ戻す。 |
| 現用名が空いていて、別の外部版が退避されている | 利用者が選択した場合だけ、再照合した外部版ハンドルを現用名へ戻す。該当する古い下書きは自動再適用できない。 |
| 現用名に別の外部版がある | 利用者の確認後にその現用版を維持し、別版の作業・退避ファイルを保持する。該当する古い下書きは自動再適用できない。 |
| 証拠が壊れている、または観測を再現できない | 適用を拒否して、ファイルを保持する。 |

回復時も新しい現用ファイルを上書きしない。退避直後の取消は、短い時間制限内に元版が照合できれば即時に元版を戻す。時間切れや競合では証拠を保持して止まる。現用名が空く段階は存在する。製品は再取得を試み、一時的な空き名を新規の空一覧として扱わない。ほかのエディターは空き名を観測できる。削除共有を許さない既存の読み手がいれば保存が拒否されることがある。

## 証拠と限界

独立した合成ファイルの子プロセスで、ハッシュ確認後の外部版導入、退避後の同名作成、両者に続く中断、退避前後の中断、公開後・後始末前の中断、同一バイトの物理ファイル切替、壊れた操作記録を検証する。保護 DACL、明示整合性ラベル、隠し属性、代替データストリームは候補への書き込み前に拒否する。外部版を選んだ記録の保持が旧下書き再適用の拒否に必要であり、人手で記録を消すと検証できない場合がある。

電源断、ファイルシステム障害、監査 SACL の保存、同一権限のプロセスが回復証拠自体を変更・削除する状況は受入未実施。固定ローカル NTFS、リパースなしのパス、対応する通常ファイルを対象とする。 [Windows ファイルセキュリティ情報](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-information)

## R18 の更新

下書き公開レシート v3 は、公開開始前に確認済みの候補ファイルの物理 ID と SHA-256 を記録する。現用ファイルが元のバイト列に戻っていても、候補がその場所に存在するだけでは、操作が公開されなかった証拠にならない。候補が消費されていないことを確認するには、通常ファイルのハンドルから ID と SHA-256 の両方を再確認する。確認不能なら下書きと候補をそのまま保持する。

v1・v2 は引き続き読み込む。公開完了が確認できる場合と、公開が始まっていないと確認できる場合の回復は維持する。公開開始済みの旧レシートには候補の証拠がないため、完了も確認できない場合は別ファイルへの退避だけを案内する。旧版へ戻す前に、v3 の回復証拠を含む回復フォルダーを退避する。

下書きファイルは作成時から公開まで無共有ハンドルで保持し、そのハンドルを使って上書きなしで公開する。公開前の取消や失敗では、そのハンドルで確認できる一時ファイルだけを後始末する。先行する下書きと現用一覧はそのまま保持する。公開後の取消は既に公開した下書きを取り消さない。下書きの読み取りでは親ディレクトリを保持して通常ファイルのハンドルを開き、読み取った内容のチェックサムを照合する。

レシートの本文形式と公開済みレシートのファイル名は維持する。公開準備中は `.publication-pending.json` を使い、公開を開始する前に、予定と一致する準備記録をハンドルから `.publication-sealed.json` へ移す。その後に開始済みレシートを正規名へ上書きなしで公開する。この間の中断では開始前の証拠が残っていないため、処理は不明として下書きと封印済み記録を保持する。正規名への公開後にのみ、同じハンドルから封印済み記録の後始末を試みる。後始末に失敗した場合も正規名の有効な証拠は利用できる。正規名の既存レシート v1〜v3 は従来どおり読み込む。旧版で新しい準備中のレシートを確認できない場合は、下書きを別ファイルへ退避する。
