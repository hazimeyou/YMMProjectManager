# 候補設計（構築未実施）

専用 Windows VM を第一候補とする。ユーザーが用意・管理できる VM と OS ライセンス、既知の YMM4 インストール元とバージョンを前提とする。既存 VM、実ユーザーデータのコピー、ホスト上の本番 plugin や profile の変更は不要とする。

1. VM の仮想ディスクを本番資産と独立させ、共有フォルダー・ホストドライブ・クリップボード・ゲスト連携のファイル転送を停止または検証。ネットワーク経由の本番データへの到達経路も除外し、資格情報や本番アカウントを置かない。
2. 専用 guest account と guest 内 test root に YMM4・plugin・fixture・ログを配置。AppData、LocalAppData、Documents、Temp、HKCU、AppDirectories.UserDirectory、作業・plugin・出力先を guest 内として実測する。
3. guest 内の試験主体が本番各保存先へ書き込めないことを、実際の共有設定と権限を確認した上で試験。証拠対象は明示的に選定し、本番パス自体への破壊的書込み試行はしない。
4. 合成ファイルで代替試験し、変更前の復旧ポイント、guest 起動時設定、特定した出力先を保存。仮想 GPU と UIA は試験機能として別途確認する。

Windows 権限変更や VM 建設を無断で行っていない。限定起動は各条件を満たして初めて検討できる。
