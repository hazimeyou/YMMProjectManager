# 隔離方式比較

| 方式 | 分離・実効境界 | GPU / UIA | 復旧・費用 | 評価 |
|---|---|---|---|---|
| 専用 Windows ユーザー | HKCU と profile は分けられるが共有フォルダー、権限、同一マシンのプラグイン / システム資源が残る。個別 deny と実効 ACL 確認が必要 | 同じハードウェアを利用できる可能性、セッションと UIA は要確認 | アカウント作成・ACL 設計・profile 廃棄の運用が必要 | 環境・実効権限を検証するまで未成立 |
| 専用 Windows VM | ゲスト profile / registry / disk がホストから分離される設計。共有ディスク、フォルダ、ホストクリップボード、ドライブ転送を無効にしてもホストからの実効到達性を検証する | 仮想 GPU / ソフトウェア描画・対話セッション・UIA の実動作が不明 | Windows ライセンス・仮想化環境・スナップショット・GPU 検証が必要 | 第一候補。現環境で未構築・未検証 |
| 単なる別ディレクトリ / 環境変数 | 本番 profile、HKCU、共有資産や host 側経路へのアクセスを防がない | 現機の描画を利用できても分離を証明しない | 低コストだが後始末・アクセス制御が不十分 | 不採用 |

OS 自体や YMM4 SDK / API のホスト差と外部ライブラリ互換性は実機検証まで未確認。VM は候補であり、セキュリティ境界の成立を前提にしていない。
