# 既知の制約

- SHA 比較直後から置換までの TOCTOU、別プロセスの競合、ファイルリンクによる別名経路は完全には防げない。安全性は同一プロセスの同一正規化パスに限定。
- Storage の公開低レベル WriteManifestAsync は caller の以前の load に結び付いた hash を持たない。実製品の作成・削除は Repository の revision 照合経路を使う。外部直接利用は未調査。
- File.Replace / Flush(true) は電源断やストレージ故障に対する完全な耐久性を保証しない。作成時の残骸削除や削除 rollback の失敗により復旧作業が必要になる場合がある。
- 旧 snapshot と同名の世代 ID が並行生成された場合の衝突対処は従来実装のまま。固定 metadata `.tmp` は今回の対象外。実ユーザーデータ形式の完全な互換性は未検証。
- 保存先ごとの semaphore はプロセス終了まで保持。巨大な Manifest では検証のため全内容をメモリへ読む。
- 独立テストと実ホスト検証は異なる。R1-A2 の YMM4 UI / ACL 未受入は未完了。cleanup 失敗・実ディスク容量不足・多プロセス競合・電源断は未検証。
