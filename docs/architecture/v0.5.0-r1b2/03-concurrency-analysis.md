# 並行保存

R1-B 基準で、合成 fixture に既存 `manifest.json.tmp` を置いて実際の storage 保存を実行すると temp が上書きされ消えた。固定名の競合による同時処理のタイミング依存実験は行っていない。

修正後、同一の正規化された Manifest パスの semaphore が temp 作成から置換までを直列化し、別パスの Manifest は互いに待たない。2つの repository load が同じ revision の場合、同時保存のうち1件が成功し、他方は stale hash で拒否されることを確認。8件の同一 project に対する同時作成では成功数と保存された増分が一致した。異なる project については障害注入 hook で両方が同時に書込み段階へ到達できることを同期 barrier で検証。固定 `.tmp` の合成先行ファイルは保持される。

パス別 semaphore はプロセス内に保持され、異なる表記やリンクが同じ実体を指すケース、別プロセスでの同時操作までは直列化しない。多くの異なる保存先を扱うと semaphore の辞書はプロセス終了まで増加する。
